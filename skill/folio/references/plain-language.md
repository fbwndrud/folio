# 쉬운 설명 — Linivera 안에서 수행하는 ELI5

## 설명의 대상부터 구분

처음 쓰는 성인에게 Linivera를 설명하는 요청과, 어린이를 독자로 작품을 만드는 요청을 구분한다.
사용법을 쉽게 설명한다고 원고의 말투·대상 연령을 바꾸지 않는다.
이미 정한 독자와 형식을 유지하고 필요한 결정만 묻는다.

## 큰 그림에서 실제 행동까지

1. 사람이 얻을 결과를 한 문장으로 말한다.
2. 낯선 개념은 익숙한 비유 하나로 설명하고 실제 의미를 바로 붙인다.
   예: "Linivera는 기록 담당처럼 승인한 글과 검사 기록을 보관합니다."
3. 한 화면에는 역할·순서·선택 중 하나를 보여 준다. 그림만으로 뜻이 전해지지 않으면
   짧은 글을 함께 넣는다. HTML을 요청하면 큰 도식과 적은 말로 첫 화면을 만들고,
   필요한 상세 절차는 펼쳐 읽게 한다. 이미지 생성은 별도 그림 요청에 맞춰 사용한다.
4. 지금 할 말과 받아야 할 결과를 함께 제시한다. 성공 기준이 보이면 다음 단계로 간다.
5. 승인·차단·저장·자료 연결·자기검토·복구의 의미와 필요한 조건을 유지한다.
   설명을 줄이면서 이 조건이 빠지면 짧은 설명 아래에 상세 설명을 붙인다.

## 사람용 본문과 연결 안내

- 사람용 본문은 작품 제목, 독자, 목표, 계획, 초안, 수정, 승인, 완성 확인을 다룬다.
- 설치 명령·절대 경로·앱별 화면은 연결 안내에 둔다. 공개 문서에 개발자의 실제 경로나
  localhost 링크를 넣지 않는다. 지금 연결한 환경의 저장 위치는 필요할 때 작가에게 확인한다.
- "작품을 고르세요"라는 가상의 버튼이나 전역 작품 목록을 만들지 않는다.
  현재 대화에서 확인한 작품을 이어가고, 모르는 작품은 위치 선택부터 안내한다.
- root가 필요한 로컬 MCP에서 경로를 감추기 위해 허구의 클라우드 기능을 설명하지 않는다.
  원고가 기록되었는지 실제 도구로 확인한다.

## 의미를 보존하는 예

| 상황 | 쉬운 설명 | 남겨야 할 의미 |
| --- | --- | --- |
| 승인 | "방금 읽은 이 글을 저장해도 되는지 골라 주세요." | 승인한 버전·범위, hard 승인 불가 |
| 참고 지적 | "살펴볼 제안입니다. 바꿀지는 작가가 고릅니다." | advisory 비자동수정 |
| 근거 연결 | "이 문장이 자료의 어느 말에서 나왔는지 함께 확인합니다." | 인용 존재가 의미의 정확성을 보증하지 않음 |
| 중단 후 재개 | "저장된 글과 남은 질문부터 읽겠습니다." | 현재 상태 확인, 내부 기록 손수정 금지 |
| 자기검토 | "쓴 AI가 다시 읽은 의견입니다." | 독립 검토·사실 인증으로 부르지 않음 |

## 완료 확인

그림의 짧은 말과 상세 본문이 같은 기능·조건을 설명하는지 대조한다.
처음 쓰는 사람이 다음에 할 행동과 성공 여부를 찾을 수 있게 한다.
실제 독자에게 시험하지 않았으면 사용성 검증을 마쳤다고 말하지 않는다.
