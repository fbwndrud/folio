# 진단과 백업 복원

작품에 이상이 있으면 먼저 쓰기를 멈추고 읽기 전용 진단을 실행한다.
설치본은 `linivera-doctor`, 소스 체크아웃은 `npm run doctor --`를 쓴다.

```sh
linivera-doctor "/path/to/work"
linivera-doctor "/path/to/work" --json
npm run doctor -- "/path/to/work" --json
```

진단은 원고와 Resource 전용 폴더를 모두 지원한다. Resource 폴더에
work.yaml이나 소설 설정을 만들지 않는다. 비어 있는 임의 폴더는 작품으로
보지 않는다. 잘못된 기존 설정·없는 폴더·권한 오류·심볼릭 링크는 오류다.
검사는 폴더 안의 일반 파일과 디렉터리만 다루고 링크·특수 파일을 따라가지 않는다.

`--json` 결과는 `{ok,checks,actions}`다. 각 check는 `name`,
`status: ok|warning|error`, `message`, 선택적인 `details`를 갖는다.
오류가 있으면 종료 코드 1, 잘못된 인자는 2다. 경고만 있으면 0이다.
이 성공 코드는 검사를 수행했다는 뜻이며 작가 승인이나 AI 품질 보증이 아니다.

## 무엇을 확인하나

- 보존된 모든 Activity record의 hash 연결과 head, 설정과 Writing status.
- Edited since review, Review needed, 열린 원고·그림 실행 및 중단된 쓰기.
- 선택 원본과 승인 결과의 보존 bytes, 입력·검토·출판 근거와 자기검토 표기.
- 현재 managed image 파일과 그 버전의 Content fingerprint 일치.
- Resources metadata 세대의 근거·최신성. 미생성·stale index와 미관측 외부
  참조는 경고이며, 손상된 bytes나 위조 근거는 오류다.

본문 손수정은 보존해야 할 작가 변경일 수 있으므로 경고와
Review and finalize changes 행동을 안내한다. pending 실행은 현재 요청·작가
결정을 확인하고 같은 버전으로 재연결하라고 안내한다. 진단은 어떤 답이나
승인도 추측하지 않는다. 손상된 실행 JSON, 알 수 없는 상태, 파일 이름과
runId 불일치는 오류이며 목록에서 생략해 정상으로 처리하지 않는다.

진단은 index·gate 파일이나 디렉터리를 만들지 않는다. 중단된 쓰기를 복구하지
않고, 본문·설정·Activity record·승인·선택을 바꾸지 않는다. 모델·네트워크도
호출하지 않는다. `actions`는 사람이 다음에 할 일이며 자동 실행되지 않는다.
동시에 작가가 파일을 수정하는 상황의 전체 작품 스냅샷 보증은 없다.
Resource 체크포인트가 읽는 동안 바뀌면 오류로 알려 다시 진단하게 한다.

## 백업과 복원 수용 순서

1. 모든 작품 호스트·MCP 서버·뷰어 및 다른 쓰기 프로세스를 종료한다.
   한 작품의 모든 기록자는 같은 Linivera 버전을 사용해야 한다. 옛 기록자와
   새 기록자를 섞어서 쓰지 않는다.
2. **작품 폴더 전체**를 별도 위치에 복사한다. 본문뿐 아니라 실제 존재하는
   설정·자료·그림·검사·exports 및 숨김 `.folio/`도 포함한다. 기록장·head,
   불변 객체·세대, run·staged image, `.lock`·gate DB와 동반 파일을 빠뜨리지 않는다.
3. 복원 시험은 기존 작품과 다른 **새 폴더**에서 한다. 기존 작품 위에
   덮어쓰거나 새 작품으로 초기화하지 않는다. 원본과 백업은 보존한다.
4. 새 폴더에 `linivera-doctor <copy> --json`을 실행한다. 오류가 있으면
   쓰기를 시작하지 않고 정상 백업과 비교한다. Activity record의 hash를
   다시 계산하거나 기록 줄을 삭제해 통과시키지 않는다.
5. 복원 사본을 조회해 예상 원고·그림·선택 원본·승인 output과 검토 기록,
   변경·승인 이력, pending 상태를 확인한다. 경고의 다음 행동을 검토한다.
6. 같은 Linivera 버전의 MCP 서버로 **복원 사본 root**에 다시 연결하고
   공개 상태·조회 도구로 이력을 확인한다. 이 단계의 일반 조회는 필요한
   파생 캐시나 잠금 파일을 만들 수 있으므로 순수 진단과 구별한다.
   일부 공개 조회도 잠금·복구 경로를 사용하므로 중단된 쓰기가 있다면
   복구를 시도할 수 있다. 진단과 백업 검토를 먼저 끝낸 뒤 도구를 선택한다.
   작가 확인 전 이어쓰기·답변·승인은 실행하지 않는다.

복사 중의 살아 있는 쓰기와 여러 폴더의 원자적 백업은 보장하지 않는다.
전원 손실·파일 시스템 손상 내구성도 약속하지 않는다. 자동 손상 복구 도구가
아니며, 진단 성공만으로 모든 캐시·과거 미선택 후보·AI 의미 품질을 보증하지 않는다.
중단·잠금·업그레이드는 [복구 안내](recovery.md)를 참고한다.

`test/diagnostics/restore.test.js`는 실제 작품 대신 합성 사본에서 전체 복사,
읽기 전용 진단·Resource 조회, 공개 MCP 두 번 재연결과 변경·승인 이력
보존을 검증한다. 자동 승인 fixture는 합성 테스트에만 사용한다.
