# Codex 내장 이미지 도구와 Folio 실사용 검증 계획

상태: 실행 중. 실제 생성·공통 인계·자기검토·오류 승인 차단을 실행했고 작가 결정을 기다린다.
실습 자료와 현재 보고서는 git에서 제외되는
`.local-output/folio-image-smoke-20261004-01/`에 보관한다.
실제 승인 해제·커밋 원고 재검사 항목은 작가 결정 이후 검증한다.

## 목적과 책임

합성 SVG로 확인한 데이터 관리 흐름을 실제 생성 이미지로 실행한다.
Codex가 이미지 생성·편집·시각 검토를 수행하고 Folio는 공통 자산 도구로
설명서·파일·버전·연결·검토·작가 결정을 관리하는지 확인한다.
Folio에 제공자 전용 코드나 API 키 설정을 추가하지 않는다.

사용 도구는 `image_gen` 내장 도구다. 별도 API/CLI로 자동 전환하지 않는다.
내장 생성 결과는 도구가 반환한 실제 파일/리소스를 확인해 인계한다.
저장 경로나 제공자 imageId를 추측하거나 만들어 넣지 않는다.
도구 호출 성공과 Folio 파일 인계 성공을 따로 기록한다.

## 작은 그림책 실습

검증 전용 새 작품에 두 펼침면을 둔다. 기존 작품은 사용하지 않는다.
작가가 보기 쉬운 짧은 글과 그림 설명을 실제 Folio 원고 실행으로 기록한다.
그림이 없어도 설명서를 먼저 관리하고, 생성 후 해당 펼침면에 연결한다.

합성 설정: 크림색 토끼, 파란 조끼, 빨간 가방. 두 장면에서 색·옷·소지품과
그림체를 유지한다. 첫 장면은 창가의 파란 공을 발견하는 모습,
둘째 장면은 같은 공을 들고 정원으로 나가는 모습이다.
이미지 안의 글자와 로고는 요구하지 않는다.
시각 설정은 작품 엔티티에, 장면별 요구는 자산 brief에 먼저 남긴다.

| 산출물 | 생성/편집 방법 | 주된 검증 |
|---|---|---|
| 첫 펼침면 A | 새 그림 생성 | 요구 준수, 실제 파일 인계와 검토 |
| 둘째 펼침면 B | A를 시각 참고로 생성 | 같은 인물·옷·소지품·그림체의 연속성 |
| A 수정본 | A를 편집 대상으로 삼아 공의 위치/구도만 변경 | 부분 편집, 유지 조건, 같은 자산 ID의 버전 교체 |
| 오류 그림 C | A를 편집해 조끼만 노란색으로 변경 | 실제 고정 설정 충돌의 발견과 hard 승인 차단 |

기본 이미지 호출은 4회다. 생성/편집 실패 또는 관찰할 수 없는 결과에 대한 추가 시도는
최대 1회로 제한한다. 추가 호출마다 이유를 기록한다. 목표와 다른 결과를 성공으로 바꾸지 않는다.
출력의 해상도·형식·용량은 실제 파일에서 측정한다. Folio의 형식 디코딩 기능으로 설명하지 않는다.

## 실행 단계와 수용 기준

1. **준비**: git에서 제외되는 새 실습 폴더, 작품·엔티티·펼침면·설명서를 준비한다.
   실제 공개 MCP 실행 파일과 stdio로 통신한다. 원고 쓰기 실행을 마친 뒤 자산을 갱신한다.
2. **생성 → 인계**: A를 생성하고 반환된 실제 결과를 실습 폴더에 보관한다.
   `folio_assets put`으로 사본을 만든다. 원본/사본 hash 일치, 용량, 렌더링을 확인한다.
   제공자 imageId가 없어도 등록되어야 한다. 응답에 실제 ID가 있으면 출처 정보로 보존한다.
   파일을 확보하지 못하면 인계 실패로 보고하며 URI를 승인된 파일처럼 취급하지 않는다.
3. **시각 검토 → 작가 결정**: Folio 사본을 직접 열고 세 고정 검사를 수행한다.
   관찰한 내용과 지적 위치를 기록한다. 같은 Codex의 자기검토로 표기한다.
   그림과 지적을 사용자에게 보여 준 뒤 사용자의 실제 승인/수정 요청을 기록한다.
   이 계획에 대한 진행 지시를 개별 그림의 품질 승인으로 해석하지 않는다.
   A를 첫 펼침면에 연결하고 원고 재검사를 마쳐 현재 자산 rev가 기록된 기준 상태를 만든다.
   이때 자산 관련 stale이 없는 것을 확인한 뒤 교체 시험으로 넘어간다.
4. **연속성**: B를 A 참고로 생성·등록하고 두 그림을 나란히 비교한다.
   설정 일치와 그림체 일치는 항목별 관찰로 보고한다. 불일치는 숨기지 않고 지적으로 남긴다.
   연속성 실패여도 데이터 관리가 통과할 수 있으므로 두 결과를 따로 판정한다.
5. **교체**: A 수정본을 같은 Folio 자산 ID에 새 버전으로 인계한다.
   옛 사본·검토·결정이 이력에 남고 현재 승인에는 쓰이지 않아야 한다.
   옛 expectedRev와 reviewId 결정 시도를 별도로 기록해 거부를 확인한다.
   새 결과를 다시 보여 주고 검토·사용자 결정을 받는다.
   먼저 승인된 A가 없다면 승인 해제 검증은 미실행으로 표시한다.
6. **의도한 오류**: C는 별도 시험 자산으로 등록하고 파란 조끼 설정과 대조한다.
   실제 노란 조끼가 관찰되면 fixed-facts 지적을 제출한다.
   시험임을 명시한 승인 요청이 hard로 거부되고 승인 기록이 생기지 않는지 확인한다.
   의도한 오류가 생성되지 않았으면 그 사례는 미성립으로 보고한다.
   Folio가 이미지 픽셀에서 충돌을 자동 발견했다고 주장하지 않는다.
7. **원고와 이어가기**: attach/get으로 두 펼침면의 사용 위치를 확인한다.
   A 교체가 관련 커밋 원고에 A의 이전/현재 rev 차이로 stale을 표시하는지 확인한다.
   원고를 recheck한 뒤 자산 관련 stale이 해소되고 본문 hash가 유지되어야 한다.
   MCP 클라이언트를 재연결해 현재 버전·결정·이력을 다시 읽는다.
8. **보고**: 각 항목을 통과/실패/미실행으로 판정하고 그림·요구 대비 관찰·MCP 응답을 연결한다.
   제품 결함이 있으면 재현 가능한 합성 회귀 테스트로 옮겨 수정하고 해당 검사를 실행한다.
   구현 변경이 없으면 이미 통과한 전체 회귀 검사를 이유 없이 반복하지 않는다.

## 저장과 보고 자료

실습 자료는 `.local-output/` 안의 새 폴더에 보관한다. 내장 도구의 기본 저장 위치에서
선택 결과를 복사하고 Folio가 다시 작품 안에 사본을 저장한다.
이 경로는 개발 실습 보관 위치이며 공개 사용법의 필수 경로로 만들지 않는다.

이미지·실제 원고·생성 프롬프트/도구 결과·MCP 호출 기록·검토·결정·실습 보고서는
커밋하지 않는다. 이 계획과 필요 시 합성 회귀 fixture만 저장소에 남긴다.
보고서에는 이미지별 실제 파일, hash, Folio ID/버전, 사용 위치,
고정 설정·필수 내용·품질 관찰, 자기검토 표시, 사용자가 내린 결정과 실행 시간을 담는다.
실제 결과를 한눈에 볼 수 있는 비교 화면도 실습 폴더에 만든다.

합성 테스트로 이미 확인한 URI·경로/용량·기록 변조·동시 쓰기 사례 전체를 다시 생성하지 않는다.
이번 실습의 통과는 Codex 한 호스트에서의 실제 연결 증거다.
모든 제공자 호환·시각 검토 정확도·유료 제품 품질을 확정하는 근거로 확대하지 않는다.
