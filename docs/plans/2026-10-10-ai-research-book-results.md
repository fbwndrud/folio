## 조사·검토

research 스킬 지시에 따라 기술·능력과 사회·경제·정책 담당을 독립 서브에이전트로
실행했다. 각 담당은 1차 자료를 열람하고 출처·시점·수치 조건·한계를 기록했다.
완성 원고의 1~6장, 7~10장에 대해 별도 후속 검토를 실제 수행했다.
사람이나 외부 전문가의 검토를 받은 것은 아니다. 모델 실험도 재현하지 않았다.

수용한 수정은 조직의 정기적 AI 이용을 한 번 사용으로 표현한 오류, 보고서의
이용률 충돌 위치, 2026년 후속 조사 누락이다. 기존 조사 노트를 덮지 않고 정정 노트를
추가하고 관련 원고와 근거 연결을 갱신했다. 기업 주장, 관측, 저자 해석과 조건부
시나리오는 구별했다. 같은 모델 계열의 검토가 공유 오류를 제거한다는 보장은 없다.

등록 자료는 AI 연구 노트이며 공식 원문 전체가 아니다. 원문 URL, 발행·관측·열람 시점,
짧은 영어 발췌, 한국어 요약과 한계를 보관한다. 57개 근거 연결의 대상은 노트의
요약 문장이다. 기계적 문장 일치는 원문 전체의 의미 검증이나 사실 인증이 아니다.

## 실제 MCP와 호스트의 경계

SDK 클라이언트로 `bin/folio-mcp.js`의 실제 stdio MCP를 연결했다.
작품 초기화·구조 생성·자료 등록·근거 연결·자산·원본 후보 등록·조회·실행·내보내기는
공개 MCP 도구로 수행했다. 조사·집필·이미지 생성은 AI 호스트가 수행했다.
원고와 개념 정의는 MCP가 만든 공개 파일 형식에 호스트가 작성했다.
정적 검토 사본은 `exportViewer` API로 생성했다. 모든 작업을 MCP 호출만으로
집필했다고 주장하지 않는다. 상세 호출은 `mcp-transcript.jsonl`에 남겼다.

실제 작품에는 작가 채택을 기록하지 않았다. 원본·초안의 generic resource는 후보로
등록했고 승인된 원본 목록이나 검색 projection generation을 꾸미지 않았다.
따라서 현재 자료 화면의 승인 목록은 준비되지 않은 상태이며 출처와 근거 화면에서
30개 연구 노트와 연결 문장을 확인할 수 있다. 후보 검토 UI는 추가 보완 대상이다.

## 실행·데이터·부정 시험

- 별도 `simulation-work` 사본에서 80개 잎의 generate/check/extract/gate/commit을
  실제 MCP로 완료했다. 모델 요청 324개를 기록했다. 호스트 응답은 프로토콜 재생이며
  승인·리뷰는 모의 결과다. AI의 독립 내용 평가나 실제 작가 채택이 아니다.
- 연결 종료 후 마지막 절의 완료 상태를 재조회했다. 실제 작품의 작가 질문 대기
  상태도 종료·재접속 뒤 동일한 runId와 질문으로 유지됨을 확인했다.
- 실제 작품의 80개 절을 전부 읽어 작성 원고와 바이트 문자열을 비교했다.
  30개 노트도 모두 읽었으며 57개 현재 근거의 위치와 노트 문장 존재를 확인했다.
- 존재하지 않는 주장 연결을 거부하고 실제 `.folio/ledger/evidence.jsonl` 바이트가
  바뀌지 않음을 확인했다. 최초 스크립트의 잘못된 ledger 경로 비교는 근거로 쓰지 않는다.
- 시험 사본에서 근거가 연결된 문장을 삭제하자 drift 1개·stale 근거 1개가 생겼다.
  조회가 원고를 자동 수정하거나 근거 기록장을 바꾸지 않았고 복원 뒤 정상으로 돌아왔다.
- 내보내기 전후 원고·설정·기록장·자원 파일 hash가 모두 같았다. 생성 출력 디렉터리는
  비교 대상에서 제외했다. 이미지의 hash·내용 검증과 승인 전 상태를 확인했다.

상세 증거: `registration-proof.json`, `correction-proof.json`, `pipeline-proof.json`,
`drift-proof.json`, `export-proof.json` 및 MCP transcript.

## 출판·실제 화면 검사

EPUB ZIP CRC, XML, mimetype 순서·비압축, 언어, nav·본문 링크, 80절 순서·제목·본문
hash를 검사했다. 80절의 렌더링된 모든 문단을 원고와 비교했고 이미지 바이트와
30개 자료 anchor가 일치했다. `epub-proof.json`에 기록했다.
외부 전자책 앱에서의 렌더링과 EPUBCheck 인증은 수행하지 않았다.

실제 브라우저로 Web 책의 전체 80절 문단을 비교했다. mismatch 0개였다.
Studio의 첫 절·중간 절·마지막 본문 절, 출처 목록·정정 상세, 자료 화면, 개념 연결
목록과 실제 참조 도표, 출판 미리보기를 열었다. 모든 화면을 전부 눈으로 읽었다는
뜻은 아니다. 데이터 전체 검사와 화면 표본 검사를 구별한다.
390px Web 화면은 가로 넘침이 없는 것을 확인했다. 스크린샷은 `shots/`에 보관한다.

## 발견해 수정한 제품 문제

| 문제 | 수정 및 확인 |
| --- | --- |
| 한국어 출판물의 영문 안내 | 출판 언어별 안내·목차·자료 목록 표시. KO/EN 합성 회귀 시험 |
| 긴 목차·경고가 본문을 밀어냄 | 목록을 접고 초안 상태는 유지. warning/manifest를 삭제하지 않음 |
| 본문·첨부에 같은 이미지 중복 | 혼합 읽기의 추가 갤러리에서 본문 이미지 제외. 그림만 1개·본문만 0개 확인 |
| EPUB에 초안 안내 누락 | EPUB 본문에 승인 전 상태 표시. XML 및 합성 회귀 시험 |
| 읽기 화면에 내부 인용 표기 노출 | 자료 제목으로 표시하고 식별자·원고·근거 offset은 유지 |
| 좁은 Web 화면에서 긴 URL 넘침 | 출판 스타일의 줄바꿈 추가. 390px scrollWidth=390 확인 |

## 자동 검증과 남은 범위

백엔드 전체 1,736개, 뷰어 전체 66개 통과. 인용 view 6개와 최신 export 시험 15개도
별도 통과했다. lint·typecheck·배포 tarball 설치 검증 통과. 변경은 기존 저장 형식과
잠금 규칙을 유지한다. 그래프 도구의 큰 lazy chunk 빌드 경고는 남아 있다.

벡터·실제 멀티모달 임베딩 실행, generic projection 세대 발행·승인, 외부 원본 전체
스냅샷, 동시 사용자 부하, 자동 최신 자료 재조사, 모든 EPUB 앱, 사람의 책 품질 평가는
이번 실습 범위 밖이다. 현재 책은 출처 기반 장문 초안과 관리·출판 흐름을 보여 주는
검토용 결과물이다. 이 성공을 전체 프로덕션 준비 완료로 확대하지 않는다.

이미지 모델은 반환된 식별자가 없어 특정 GPT Image 2.5라고 기록하지 않았다.
공식 API 제품 안내와 이번 내장 실행의 모델·계정 가용성은 구별한다.

롤백은 기존 작품을 건드리지 않고 ignored 실습 폴더를 격리하는 방식이다.
초기 내보내기는 백업 폴더로 보관했고 수정 후 새 폴더로 다시 출력했다.
