# Folio N2 자료 근거 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 논픽션의 주장과 자료를 잇는다. 코어에 근거 연결(추가만 되는 기록장 `.folio/ledger/evidence.jsonl`, 주장 인용 ↔ 자료 인용을 엔진이 양쪽 대조), 추출 답의 선택 필드 `claims`, 요청 payload의 자료 설명을 더하고, 둘째 팩 `packs/sources`(결정론 검사 셋, 모델 검사 둘, 세트 둘 — 모두 실험·참고 의견), knowledge 팩 프리셋 `sourcebook`, 새 MCP 도구 `folio_sources`(add · list · get · link)를 만든다. 코어 잠금은 어느 토글·세트와도 무관하다.

**Architecture:** 등장 위치(M4)와 같은 모양이다. 엔진은 주장을 스스로 찾지 않는다 — 호스트가 추출 답(`evidence.wanted`일 때)이나 `folio_sources link`로 주장 인용과 자료 인용을 내고, 엔진은 주장 쪽을 M4 `resolveQuote`(코드 블록 밖, 한 곳)로, 자료 쪽을 원본 글(.txt/.md) 또는 설명서 `spans`로 대조해 하나라도 틀리면 전부 거부한다. 커밋 뒤 추출 주장은 origin `extract`로, 도구 제출은 origin `tool`로 기록장에 쌓인다. 범위(`gatherScope`)가 주장을 받아 검사 ctx(`claims`)와 refs(주장이 연결한 자료)를 넓히고, 재검사·다시 커밋은 기록장의 주장을 본다. 본문이 바뀌면 M4 `reanchor`로 연결이 stale이 된다. 검사는 둘째 팩이 이름 검사기로 보탠다(단계·프롬프트·프리셋은 첫 팩).

**Tech Stack:** Node ESM + JSDoc, `node:test`, `yaml`, `@modelcontextprotocol/sdk`(1.x, stdio), ESLint 9 + TypeScript(`checkJs`).

**Spec:** 승인된 N2 설계(사용자 승인 2026-09-28 "ㅇㅇ ㄱ") — 세션 scratchpad의 `n2-design.md`. 이 계획의 "설계 요약" 절에 그대로 옮겨 두었다(세션이 바뀌어도 읽을 수 있게). 설계 결정은 다시 열지 않고, 빈 곳만 "결정" 표로 채웠다. 설계 정본 아티팩트 https://claude.ai/artifact/WjJzcsjnQZnVxyyJZaxvcX §13 자료 근거, §16 도구. 범위 결정: `docs/plans/2026-09-27-scope-nonfiction-decision.md`. 계속 유효한 판정: `docs/plans/2026-09-27-n1-knowledge-pack-rulings.md`(프롬프트는 실제 payload 필드만 가리킴, 코어 `stamp`의 지적 severity 후속 과제), `docs/plans/2026-09-27-m4-occurrences-rulings.md`(A3-1·A3-4 다시 찾기 규칙, B1-1 모양 틀린 기록 건너뜀, B3-2·B3-3 추출 기록 규칙, P11 기록 실패는 커밋을 묶지 않음, F-2 부모 토글).

## 설계 요약 (승인본에서 옮김)

- 지금 코드: `core/store/sources.js`(설명서 읽기, `rev`, 한 번 쓰기 원본), 노드 앞머리 `sources: [...]` → `gatherScope`의 `sources`, refs `{kind:'source'}`, `core/scope/stale.js`가 rev 비교. M4 표면에 `source`(설명서 글 leaf, 원본 파일은 표면 아님). 없는 것: 근거 연결, 근거 검사, `folio_sources`, payload의 자료. 팩은 도구를 못 더한다. 둘째 팩은 검사·세트만 보탠다(파이프라인·프롬프트·프리셋은 첫 팩).
- **§1 구조**: 둘째 팩 `packs/sources` + 코어 근거 연결 + 도구 하나.
  - 코어 근거 연결: 추가만 되는 기록장 `.folio/ledger/evidence.jsonl`(M4 등장 위치와 같은 방식). 기록 하나 = 노드 본문 주장 인용(+앞뒤 문맥) ↔ 자료 id + 자료 인용. 엔진이 양쪽을 대조한다: 본문 쪽은 코드 블록 밖, 자료 쪽은 원본이 글 파일(.txt/.md)이면 원본에서, 아니면(PDF 등) 설명서 `spans`의 인용과 같아야 한다. 본문이 바뀌면 M4 다시 찾기 규칙(`core/occurrences/anchor.js`)으로 stale. 자료 원본은 한 번 쓰기라 움직이지 않는다.
  - `packs/sources`: 둘째 팩으로 붙는다(`packs: [knowledge, sources]`). 소설에도 붙일 수 있다.
  - 새 도구 `folio_sources` — op `add`(글 `text` 또는 로컬 파일 `path`를 `sources/`로 복사 + 설명서 작성, 원본은 덮지 않음), `list`, `get`, `link`(근거 연결 제출, 틀린 인용이 하나라도 있으면 전부 거부). 도구 11개.
- **§2 주장을 누가 찾나**: 엔진은 주장을 스스로 못 찾는다. 추출 답에 선택 필드 `claims: [{ quote, sources: [{ sourceId, quote }] }]` — 요청 payload의 `evidence.wanted`가 true일 때만 요청한다(M4 occurrences와 같은 모양). 틀리면 기존 재요청 규칙. 커밋 뒤 origin `extract`로 기록한다. 호스트가 주장을 빼먹는 것은 모델 검사가 보완한다.
- **§3 검사** — 모두 experimental, advisory. 작가만 block으로 올림(hard 불가).

  | 검사 | 종류 | 보는 것 |
  |---|---|---|
  | `sources.claim-supported` | 결정론 | 추출된 주장 중 확인된 근거가 없는 것 |
  | `sources.numbers-match` | 결정론 | 주장 인용의 숫자·연도가 연결된 자료 인용에 없음 |
  | `sources.reliability` | 결정론 | `reliability: low` 자료에만 기댄 주장 |
  | `sources.conflict` | 모델 critic | 연결된 자료끼리 어긋남 |
  | `sources.claims-found` | 모델 critic | 표시 안 된 주장 |

  세트: `sources.citations`(논픽션 인용 = 결정론 셋), `sources.review`(모델 둘). `defaultCheckSets` 없음(`recommendedFor`로 추천만).
- **§4 자료로 뼈대 만들기**: 코어 payload에 범위 안 자료(`id, title, date, reliability, spans`)를 싣는다(작은 코어 변경). knowledge 팩에 프리셋 `sourcebook`(자료 책: part → chapter → section, checkSets `[knowledge.basic, sources.citations]`, `packs: [knowledge, sources]` 필요). 흐름: `folio_sources add` → 루트 노드 앞머리 `sources` → 위층 계획 프롬프트가 자료로 목차 초안 → 보통 계획처럼 점검·승인. 엔티티 초안은 호스트가 파일로 쓴다(스킬 문서 안내).
- **§5 토글**(work.yaml `features`): `sources: true`(끄면 도구가 `FEATURE_DISABLED`), `evidence: true`, `evidenceInExtract: true`(evidence 필요). 잠금은 어느 토글과도 무관.
- **§6 완료 기준**(`test/acceptance/n2.test.js`, MCP stdio): 1 자료 add/list/get, 틀린 인용 link는 전부 거부. 2 근거 없는 주장이 advisory로 나오고, block으로 올리면 막힘. 3 숫자·연도 불일치를 잡음. 4 신뢰도 낮은 자료만 쓴 주장을 잡음. 5 근거 걸린 본문을 고치면 연결이 stale, 자료 설명서가 바뀌면 노드가 다시 확인 필요. 6 토글·세트를 끄면 그 검사가 안 돌고 잠금은 그대로. 7 `sourcebook` 작품의 루트 계획 요청에 자료가 실림.
- **범위 밖**: PDF 텍스트 추출, 웹 가져오기, 자료끼리 충돌의 결정론 판정, 인용 형식·각주·참고문헌(N3).
- **사용자가 확인한 선택**: (a) 근거 검사를 knowledge 팩 안이 아닌 별도 둘째 팩 `sources`에 둔다. (b) `add`가 로컬 경로(`path`)도 받는다.

## Global Constraints

- 이름 `Folio`, MCP 도구 접두어 `folio_`, 작품 내부 폴더 `.folio/`.
- `package.json` `"engines": { "node": "^22.13.0 || ^24.0.0 || ^26.0.0" }`, `"type": "module"`. 런타임 의존성은 `yaml`과 `@modelcontextprotocol/sdk` 둘뿐이다. 늘리지 않는다. 네이티브 모듈은 금지다.
- 엔진은 모델을 부르지 않는다: `needs_model`/`needs_user`를 돌려주고 `folio_resume`/`folio_decide`로 이어 간다. `core/`와 `packs/`는 모델·네트워크를 부르지 않는다(`test/core/no-model-calls.test.js`). `server/`만 SDK를 import한다. 팩 검사기는 순수 함수다(파일도 읽지 않는다).
- `server/`는 코어 쓰기 경로를 import하지 않는다(`test/server/tools.test.js` 가드): `core/run/commit.js`, `core/run/recheck-commit.js`, `core/structure/ops.js`, `core/ledger/ledger.js`, `core/store/tree.js`, `core/util/file-tx.js`, `core/util/file-tx-journal.js`, 그리고 이 계획이 더하는 `core/store/sources.js`(원본·설명서 쓰기), `core/evidence/record-run.js`(잠금 없이 근거 기록장에 쓰는 길). 서버는 스스로 작업 잠금을 잡는 공개 함수(`addSource`, `submitEvidence`, `listSources`, `getSource`)만 부른다.
- 잠금 규칙(설정·팩·검사 세트·기능 토글로 끌 수 없음): 커밋 원고 hash = 검사 원고 hash · 영수증 없이 커밋 금지 · 켜 둔 검사의 hard 판정은 커밋을 막고 승인으로 넘길 수 없음 · 기록장은 추가만(근거 기록장 포함) · 같은 호스트 자기검토를 독립 평가로 표기 금지 · soft·참고 의견은 자동 수정 사유 아님 · `core.promise-order`는 어떤 세트·토글에서도 돈다.
- 팩은 잠금을 선언할 수 없다(`pack.yaml`에 `locked` 없음). 팩 검사기는 지적에 `severity`를 적지 않는다 — 등급은 `pack.yaml`과 작가 설정(`severityOverride`)만 정한다.
- 새 검사는 `experimental: true`, `severity: advisory`로 시작한다(§12). 작가만 `block`으로 올린다. `hard`로는 올릴 수 없다.
- 검사 세트는 작가가 고른다. 추천만 하고 강제하지 않는다(`sources` 팩은 `defaultCheckSets`가 없다). 새 기능은 모두 work.yaml `features`로 끄고 켤 수 있어야 한다(`sources`, `evidence`, `evidenceInExtract`). 잠금은 토글이 아니다.
- 테스트 데이터는 전부 합성이다. 임시 폴더는 `test/support/fixtures.js`의 `tempDir`/`copyFixture`만 쓴다. 원본 fixture 파일을 고치지 않는다. 작가의 손 작업(work.yaml·설명서·노드 앞머리·본문 고치기)은 테스트가 복사본에 한다.
- `folio_sources add`의 `path`는 작품을 `sources/` 밖으로 내보내지 않는다: 복사본 이름은 id와 정리한 확장자로만 만들고(한 번 쓰기), 읽는 것은 작가가 고른 절대 경로의 보통 파일 하나뿐이며 결과에 읽은 경로·크기·hash를 밝힌다.
- 파일 하나에 한 책임. 300줄을 넘기면 나눈다.
- 문서·주석 설명은 한국어, 코드 식별자는 영어. 커밋 메시지는 영어 Conventional Commits, 끝에 정확히 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `.superpowers/`는 커밋하지 않는다. 각 Task는 자기 파일만 커밋한다. `/path/to/vibelore`는 읽기 전용이다(이 계획은 쓰지 않는다).
- TDD: 실패하는 테스트 → 실패 확인 → 구현 → 통과 → `npm run check` 전부 초록 → 커밋. 기존 테스트의 assert를 약화하지 않는다. 기존 테스트를 바꾸는 곳은 이 계획이 이유와 함께 적은 곳뿐이다(결정 15).
- 머신 부하가 높으면 전체 테스트가 몇 분 걸릴 수 있다. 느려졌다고 회귀로 단정하지 말고 같은 조건에서 기준 커밋과 비교한다.
- 리뷰: 검사·잠금·범위·기록장·작품 밖 파일 경로를 건드리는 Task(A1, A2, A3, B1, B3)는 가장 강한 리뷰어 모델에 맡기고, 각 Task의 "공격해 볼 것"을 시도하게 한다. B2는 보통 모델, C1은 최종 브랜치 리뷰(가장 강한 모델)에 합친다.
- 마일스톤 정지: Task C1(N2 완료 기준)이 끝나면 결과를 보여 주고 멈춘다. main 병합·push·PR은 사용자에게 묻는다. N3는 사용자 확인 전에 시작하지 않는다.

/** 자료 인용 길이 한도(주장 인용·등장 위치 인용과 같다). */
export const MAX_SOURCE_QUOTE = 500;
const nfc = (text) => text.normalize('NFC');

/**
 * 자료 인용이 그 자료에 정말 있는가(N2 설계 §1 "엔진이 양쪽을 대조한다").
 * - 글 파일(.txt/.md) 자료: 원본 글에 그대로 있어야 한다.
 * - 그 밖(PDF 등 글을 읽지 않는 자료): 설명서 spans 의 인용 하나와 같아야 한다(앞뒤 공백만 무시한다. 일부만 인용하면 안 된다).
 * NFC 로 견준다. 다듬은 길이 2 미만이거나 500자를 넘는 인용은 근거가 아니다.
 * @param {{ text?: string|null, spans?: any[] } | undefined} source
 * @param {unknown} quote
 * @returns {{ ok: true } | { ok: false, code: 'CLAIM_SOURCE_UNKNOWN'|'CLAIM_SOURCE_QUOTE_INVALID'|'CLAIM_SOURCE_QUOTE_NOT_FOUND' }}
 */
export function checkSourceQuote(source, quote) {
  if (!source) return { ok: false, code: 'CLAIM_SOURCE_UNKNOWN' };
  if (typeof quote !== 'string' || quote.trim().length < 2 || quote.length > MAX_SOURCE_QUOTE) return { ok: false, code: 'CLAIM_SOURCE_QUOTE_INVALID' };
  const wanted = nfc(quote);
  const found = typeof source.text === 'string'
    ? nfc(source.text).includes(wanted)
    : (Array.isArray(source.spans) ? source.spans : []).some((span) => typeof span?.quote === 'string' && nfc(span.quote).trim() === wanted.trim());
  return found ? { ok: true } : { ok: false, code: 'CLAIM_SOURCE_QUOTE_NOT_FOUND' };
}

 * - 주장 인용: 다듬은 길이 2 이상, 500자 이하. 본문(코드 블록 밖)의 한 곳으로 정해져야 한다(M4 resolveQuote — 여럿이면 before/after 로 좁힌다).
 * - 같은 위치에서 시작하는 주장이 둘이면 CLAIM_DUPLICATE.
 * - 연결(sources): 20개까지. 자료가 있어야 하고 자료 인용이 그 자료에 있어야 한다(checkSourceQuote). 같은 연결은 한 번만 남긴다.
 * - 근거 없는 주장(sources: [])도 받는다 — 그것을 알리는 것이 sources.claim-supported 검사다.
 * - 앞뒤 문맥은 엔진이 본문에서 다시 자른 것으로 바꾼다(호스트가 준 문맥을 그대로 저장하지 않는다).
 * @param {{ sources: Map<string, any> }} work
 * @param {string} text
 * @param {unknown} claims
 */
export function validateClaims(work, text, claims) {
  if (!Array.isArray(claims) || claims.length > MAX_CLAIMS) return { claims: [], errors: [{ index: null, code: 'CLAIMS_SHAPE_INVALID' }] };
  const errors = [];
  const accepted = [];
  const starts = new Set();
  for (let index = 0; index < claims.length; index += 1) {
    const claim = claims[index];
    if (!isPlainObject(claim) || !Array.isArray(claim.sources) || claim.sources.length > MAX_LINKS) { errors.push({ index, code: 'CLAIM_INVALID' }); continue; }
    if (typeof claim.quote !== 'string' || claim.quote.trim().length < 2 || claim.quote.length > MAX_QUOTE) { errors.push({ index, code: 'CLAIM_QUOTE_INVALID' }); continue; }
    const found = resolveQuote(text, { quote: claim.quote, before: claim.before, after: claim.after });
    if (found.ok === false) {
      errors.push({ index, code: found.code.replace(/^OCCURRENCE_/, 'CLAIM_'), ...(found.count !== undefined ? { count: found.count } : {}) });
      continue;
    }
    if (starts.has(found.start)) { errors.push({ index, code: 'CLAIM_DUPLICATE' }); continue; }
    const links = [];
    let refused = null;
    for (let at = 0; at < claim.sources.length && !refused; at += 1) {
      const link = claim.sources[at];
      const sourceId = isPlainObject(link) ? link.sourceId : undefined;
      const known = typeof sourceId === 'string' && work.sources.has(sourceId);
      const checked = checkSourceQuote(known ? work.sources.get(sourceId) : undefined, link?.quote);
      if (checked.ok === false) refused = { index, link: at, code: checked.code, ...(sourceId !== undefined ? { sourceId: clip(sourceId) } : {}) };
      else if (!links.some((l) => l.sourceId === sourceId && l.quote === link.quote)) links.push({ sourceId, quote: link.quote });
    }
    if (refused) { errors.push(refused); continue; }
    starts.add(found.start);
    accepted.push({ quote: claim.quote, before: found.before, after: found.after, sources: links });
  }
  return { claims: accepted, errors };
}

/**
 * 기록된 근거 연결이 지금 본문·자료에서 어떤지. 파일이 정본이고 이 결과는 매번 새로 계산한다.
 * - 주장 위치: 노드가 없으면 stale(NODE_MISSING), 아니면 M4 다시 찾기(reanchor)로 located/relocated/stale. 짐작하지 않는다.
 * - 연결마다 verified: 지금 자료에 그 인용이 있는가. 원본은 한 번 쓰기라 움직이지 않지만 설명서(spans)와 자료 목록은 바뀔 수 있다.
 * @param {{ tree: { nodes: Map<string, any> }, sources: Map<string, any> }} work
 * @param {any[]} records
 */
export function evidenceStates(work, records) {
  const out = [];
  for (const record of latestByNode(records).values()) {
    const node = work.tree.nodes.get(record.nodeId);
    for (const claim of record.claims) {
      const at = node ? reanchor(node.body, claim) : { status: 'stale', start: null, reason: 'NODE_MISSING' };
      const sources = claim.sources.map((link) => ({
        sourceId: link.sourceId, quote: link.quote, verified: checkSourceQuote(work.sources.get(link.sourceId), link.quote).ok,
      }));
      out.push({ nodeId: record.nodeId, quote: claim.quote, before: claim.before, after: claim.after, sources, origin: record.origin, seq: record.seq, ...at });
    }
  }
  return out;
}

import { sha256 } from '../util/hash.js';
import { validateClaims } from './validate.js';

/**
 * 커밋이 끝난 실행의 추출 주장을 근거 기록장에 남긴다(origin extract). 같은 영수증으로 두 번 쓰지 않는다(커밋 재개 멱등).
 * 실행 파일의 주장은 믿지 않는다: 커밋된 원고(hash = 실행 draftHash)와 지금 자료로 다시 대조해 모두 맞아야 쓴다.
 * origin 'extract' 는 evidenceInExtract 가 켜져 있었다는 뜻이므로 evidence·evidenceInExtract 가 다 켜져 있어야 쓴다(M4 Ruling B3-2 와 같은 규칙).
 * 틀리면 EVIDENCE_INVALID 로 던진다 — 호출자(commitStep)가 잡아 실행 기록(history)에 남긴다. 근거 기록은 잠금 판단에 쓰이지 않으므로 커밋은 막지 않는다.
 * @param {{ ledger: { readAll: () => Promise<any[]>, append: (entry: any) => Promise<any> }, ctx: any, run: any, receiptId: string }} params
 */
export async function recordRunEvidence({ ledger, ctx, run, receiptId }) {
  const events = run.outputs.events;
  const features = ctx.work.config.features;
  if (!features.evidence || !features.evidenceInExtract || events?.submittedClaims !== true) return null;
  const records = await ledger.readAll();
  if (records.some((r) => r.type === 'evidence' && r.receiptId === receiptId)) return null;
  const text = run.outputs.draft;
  if (typeof text !== 'string' || sha256(text) !== run.draftHash) {
    throw new FolioError('EVIDENCE_INVALID', `${run.runId}: committed text no longer matches the run's draftHash`);
  }
  const { claims, errors } = validateClaims(ctx.work, text, events.claims);
  if (errors.length) throw new FolioError('EVIDENCE_INVALID', `${run.runId}: claims failed re-validation against the committed text`, { errors: errors.slice(0, 50) });
  return ledger.append({ type: 'evidence', nodeId: run.nodeId, textHash: run.draftHash, claims, origin: 'extract', receiptId });
}

 * 검사가 보는 이 원고의 주장(ctx.claims, N2 §2). 연결은 지금 자료로 다시 확인한 것만 남긴다 — "확인된 근거"만 근거로 센다.
 * - evidence 기능이 꺼져 있으면 없다(기록장도 읽지 않는다 — 러너가 records 를 null 로 준다).
 * - 이 실행의 추출 답이 주장을 냈으면(submittedClaims) 그것.
 * - 아니면 원고가 파일 본문과 같을 때(재검사·다시 커밋) 근거 기록장의 이 노드 최근 기록 가운데 지금 본문에서 다시 찾은 주장.
 * - 그 밖에는 없다: 새로 쓴 원고에 옛 기록의 주장을 대지 않는다.
 * @param {{ work: any, records: any[]|null, nodeId: string, draft: string, extracted: any }} input
 * @returns {Array<{ quote: string, sources: Array<{ sourceId: string, quote: string }> }>}
 */
export function claimsFor({ work, records, nodeId, draft, extracted }) {
  if (!work.config.features.evidence) return [];
  const verified = (claim) => ({
    quote: claim.quote,
    sources: claim.sources.filter((link) => checkSourceQuote(work.sources.get(link.sourceId), link.quote).ok)
      .map(({ sourceId, quote }) => ({ sourceId, quote })),
  });
  if (extracted?.submittedClaims === true) return (Array.isArray(extracted.claims) ? extracted.claims : []).map(verified);
  const node = work.tree.nodes.get(nodeId);
  if (!node || draft !== node.body) return [];
  const record = latestByNode(records ?? []).get(nodeId);
  if (!record) return [];
  return record.claims.filter((claim) => reanchor(node.body, claim).status !== 'stale').map(verified);
}

export const claimsOf = (ctx) => (Array.isArray(ctx?.claims) ? ctx.claims : [])
  .filter((claim) => claim && typeof claim.quote === 'string' && Array.isArray(claim.sources));

/** 주장이 연결한 자료 id(한 번씩, 처음 나온 순서). */
export const sourceIdsOf = (claim) => [...new Set(claim.sources.map((link) => link?.sourceId).filter((id) => typeof id === 'string'))];

/** 자료 설명서의 신뢰도(다듬고 소문자로). 자료가 없거나 적지 않았으면 null. */
export function reliabilityOf(ctx, sourceId) {
  const value = ctx?.work?.sources?.get?.(sourceId)?.reliability;
  return typeof value === 'string' ? value.trim().toLowerCase() : null;
}

/** 천 단위 쉼표(1,000 → 1000)를 빼고 앞의 0을 뗀다(07 → 7). 소수점은 둔다. */
const normalizeNumber = (raw) => (/^\d{1,3}(,\d{3})+(\.\d+)?$/.test(raw) ? raw.replace(/,/g, '') : raw).replace(/^0+(?=\d)/, '');

/**
 * 글 속 아라비아 숫자(연도 포함)를 한 번씩, 나온 순서로. NFKC 로 전각 숫자(２０２６)를 바꾼 뒤 읽는다.
 * 한글 숫자(삼십칠조)는 읽지 않는다(결정 11).
 * @param {unknown} text
 */
export function numbersIn(text) {
  const found = String(text ?? '').normalize('NFKC').match(/\d+(?:[.,]\d+)*/g) ?? [];
  return [...new Set(found.map(normalizeNumber))];
}

import { claimsOf, numbersIn } from './claims.js';

/**
 * 숫자·연도 대조(sources.numbers-match). 주장 인용의 숫자·연도 가운데 그 주장에 연결된 자료 인용 어디에도 없는 것을 알린다.
 * 한 주장의 연결 전체를 합쳐 본다(자료 둘에 나눠 있으면 인정). 근거 없는 주장은 sources.claim-supported 몫이라 건너뛴다.
 * 등급은 pack.yaml(advisory)과 작가 설정이 정한다. 지적에 severity 를 적지 않는다.
 * @param {{ claims?: unknown }} ctx
 */
export function numbersMatch(ctx) {
  const findings = [];
  for (const claim of claimsOf(ctx)) {
    if (claim.sources.length === 0) continue;
    const backed = new Set(claim.sources.flatMap((link) => numbersIn(link?.quote)));
    const missing = numbersIn(claim.quote).filter((n) => !backed.has(n));
    if (missing.length === 0) continue;
    findings.push({
      code: 'NUMBER_NOT_IN_SOURCE', quote: claim.quote, numbers: missing,
      message: `"${claim.quote}": ${missing.join(', ')}이(가) 연결된 자료 인용에 없다`,
    });
  }
  return findings;
}

/**
 * 자료 신뢰도(sources.reliability). 연결된 자료가 모두 신뢰도 낮음(reliability: low)인 주장을 알린다.

export function lowReliability(ctx) {
  const findings = [];
  for (const claim of claimsOf(ctx)) {

    });
  }
  return findings;

import { constants } from 'node:fs';
import { open, stat, unlink, writeFile } from 'node:fs/promises';
import { extname, isAbsolute, join } from 'node:path';
import { FolioError } from '../errors.js';
import { ID } from '../store/ids.js';
import { openWork } from '../store/work.js';
import { SOURCES_DIR, addSourceFile, isTextSourceFile } from '../store/sources.js';
import { withWorkLock } from '../run/work-lock.js';
import { assertFeature } from '../work/features.js';
import { sha256 } from '../util/hash.js';
import { stringifyYaml } from '../util/yaml.js';

/** 한 자료 원본의 크기 한도. */
export const MAX_SOURCE_BYTES = 10 * 1024 * 1024;
/** 설명서 reliability 로 받는 값. sources.reliability 검사는 low 만 본다. */
export const RELIABILITIES = Object.freeze(['low', 'medium', 'high']);
const MAX_SPANS = 200;
const cut = (value) => String(value).slice(0, 300);

/**
 * 작가가 고른 로컬 파일 하나를 그대로 읽는다(N2 결정 17). 절대 경로, 링크가 아닌 보통 파일, 10MiB 까지.
 * O_NOFOLLOW 로 링크를 따라가지 않고, O_NONBLOCK 으로 FIFO 에서 멈추지 않는다. 연 뒤 fstat 으로 보통 파일인지 본다(검사와 읽기 사이 바꿔치기 없음).
 * @param {unknown} path
 * @returns {Promise<Buffer>}
 */
async function readLocalFile(path) {
  if (typeof path !== 'string' || !isAbsolute(path) || path.includes('\0')) {
    throw new FolioError('SOURCE_PATH_INVALID', 'path must be an absolute path to one file', { path: cut(path) });
  }
  let handle;
  try {
    handle = await open(path, constants.O_RDONLY | (constants.O_NOFOLLOW ?? 0) | (constants.O_NONBLOCK ?? 0));
  } catch (error) {
    throw new FolioError('SOURCE_PATH_INVALID', 'cannot open the file (missing, a link, or not readable)', { path: cut(path), errno: error?.code ?? null });
  }
  try {
    const info = await handle.stat();
    if (!info.isFile()) throw new FolioError('SOURCE_PATH_INVALID', 'not a regular file', { path: cut(path) });
    if (info.size > MAX_SOURCE_BYTES) throw new FolioError('SOURCE_TOO_LARGE', `${info.size} bytes`, { path: cut(path), bytes: info.size, max: MAX_SOURCE_BYTES });
    const bytes = await handle.readFile();
    if (bytes.length > MAX_SOURCE_BYTES) throw new FolioError('SOURCE_TOO_LARGE', `${bytes.length} bytes`, { path: cut(path), bytes: bytes.length, max: MAX_SOURCE_BYTES });
    return bytes;
  } finally {
    await handle.close();
  }
}

/** 복사본 확장자: 원래 확장자(소문자, 영숫자 1~8자)를 쓰고, 아니면 .bin. 글(text)은 .txt. */
const suffixOf = (path) => {
  const ext = extname(path).toLowerCase();
  return /^\.[a-z0-9]{1,8}$/.test(ext) ? ext : '.bin';
};

/** spans: [{ id, quote }]. id 는 작품 id 규칙, 중복 없음. 글 자료면 인용이 그 글(NFC)에 있어야 한다. */
function readSpans(spans, text) {
  if (spans === undefined) return [];
  if (!Array.isArray(spans) || spans.length > MAX_SPANS) throw new FolioError('SOURCE_SPANS_INVALID', 'spans must be a list of { id, quote }');
  const seen = new Set();
  return spans.map((span, index) => {
    const valid = span && typeof span === 'object' && typeof span.id === 'string' && ID.test(span.id) && !seen.has(span.id)
      && typeof span.quote === 'string' && span.quote.trim().length >= 2 && span.quote.length <= 500;
    if (!valid) throw new FolioError('SOURCE_SPANS_INVALID', `span ${index}`, { index });
    if (text !== null && !text.normalize('NFC').includes(span.quote.normalize('NFC'))) {
      throw new FolioError('SOURCE_SPAN_NOT_FOUND', `span ${span.id} is not in the source text`, { index, spanId: span.id });
    }
    seen.add(span.id);
    return { id: span.id, quote: span.quote };
  });
}

const exists = (path) => stat(path).then(() => true, (error) => (error?.code === 'ENOENT' ? false : Promise.reject(error)));

/**
 * 자료 하나를 더한다(folio_sources add). 글(text) 또는 로컬 파일(path) 중 하나를 sources/<id>.<확장자>로 한 번만 쓰고 설명서 sources/<id>.yaml 을 쓴다.
 * - 원본은 덮지 않는다: 같은 id 의 자료·설명서가 있으면 SOURCE_EXISTS, 같은 이름의 원본만 남아 있으면 SOURCE_IMMUTABLE(addSourceFile).
 * - 파일 이름은 id(작품 id 규칙)와 정리한 확장자로만 만든다 — 호스트가 준 이름·경로 조각은 쓰지 않는다(sources/ 밖으로 못 나간다).
 * - 모든 검증(spans 포함)이 끝난 뒤에 쓴다. 설명서 쓰기가 실패하면 이 호출이 방금 쓴 원본만 지운다.
 * - 읽은 파일은 결과의 read 에 경로·바이트 수·hash 로 밝힌다. 작업 잠금 안에서 돈다. sources 기능이 켜져 있어야 한다.
 * @param {string} root
 * @param {{ id?: unknown, title?: unknown, date?: unknown, reliability?: unknown, spans?: unknown, text?: unknown, path?: unknown }} input
 */
export async function addSource(root, input) {
  return withWorkLock(root, async () => {
    const work = await openWork(root);
    assertFeature(work.config, 'sources');
    const { id, title = '', date = null, reliability = null, spans, text, path } = input ?? {};
    if (typeof id !== 'string' || !ID.test(id) || id.length > 100) throw new FolioError('ID_INVALID', `source.id: ${cut(id)}`);
    if ((text === undefined) === (path === undefined) || (text !== undefined && (typeof text !== 'string' || text.length === 0))) {
      throw new FolioError('SOURCE_INPUT_INVALID', 'give exactly one of text (non-empty) or path');
    }
    if (typeof title !== 'string' || (date !== null && typeof date !== 'string') || (reliability !== null && !RELIABILITIES.includes(/** @type {any} */ (reliability)))) {
      throw new FolioError('SOURCE_INPUT_INVALID', 'title and date are strings; reliability is low, medium or high', { reliabilities: RELIABILITIES });
    }
    if (work.sources.has(id) || await exists(join(root, SOURCES_DIR, `${id}.yaml`))) throw new FolioError('SOURCE_EXISTS', id, { id });
    const bytes = typeof text === 'string' ? Buffer.from(text, 'utf8') : await readLocalFile(path);
    const file = `${id}${typeof text === 'string' ? '.txt' : suffixOf(path)}`;
    const cleanSpans = readSpans(spans, isTextSourceFile(file) ? bytes.toString('utf8') : null);
    const meta = { id, title, file, ...(date !== null ? { date } : {}), ...(reliability !== null ? { reliability } : {}), spans: cleanSpans };
    await addSourceFile(root, file, bytes);
    try {
      await writeFile(join(root, SOURCES_DIR, `${id}.yaml`), stringifyYaml(meta), { flag: 'wx' });
    } catch (error) {
      await unlink(join(root, SOURCES_DIR, file)).catch(() => {});
      throw error;
    }
    return {
      source: { id, title, file, date, reliability, spans: cleanSpans },
      read: typeof text === 'string' ? null : { path, bytes: bytes.length, sha256: sha256(bytes) },
    };
  });
}

export async function sourcesTool(root, { op, ...args }) {
  const rule = ARGS[op];
  const missing = rule.required.filter((key) => args[key] === undefined);
  const extra = Object.keys(args).filter((key) => !rule.allowed.includes(key));

  if (op === 'list') return listSources(root);
  if (op === 'get') return getSource(root, args.id);
  return submitEvidence(root, { nodeId: args.nodeId, claims: args.claims });
}

# 자료와 근거 (sources 팩, `folio_sources`)

엔진은 주장을 스스로 찾지 않는다. 호스트가 주장 문장과 그것을 받치는 자료 인용을 내고, 엔진은 둘 다 정말 있는지만 대조한다.

## 준비

- 작품 `packs`에 `sources`를 둘째 팩으로 둔다: `packs: [knowledge, sources]`(소설이면 `[novel, sources]`). 자료 책은 `folio_init { preset: 'sourcebook', packs: ['knowledge', 'sources'] }`([knowledge.md](knowledge.md)).
- 검사 세트는 작가가 고른다: `sources.citations`(결정론 셋), `sources.review`(모델 둘). 둘 다 실험·참고 의견이다. 기본 세트는 없다.
- 기능 토글(work.yaml `features`): `sources`(도구와 요청의 자료), `evidence`(근거 연결), `evidenceInExtract`(추출 요청이 주장을 묻는다). 끄는 것은 작가가 정한다. 잠금은 어떤 토글과도 상관없다.

## 자료 넣기 — `folio_sources { root, op: 'add', id, title?, date?, reliability?, spans?, text | path }`

- `text`: 글을 그대로 `sources/<id>.txt`로 쓴다. `path`: 작가가 고른 파일 하나를 `sources/<id>.<확장자>`로 복사한다. 절대 경로, 링크가 아닌 보통 파일, 10MiB까지다. 결과 `read`에 읽은 경로·바이트 수·hash가 온다 — 작가가 고른 파일만 넘기고, 읽은 것을 작가에게 알린다.
- 원본은 한 번만 쓴다. 같은 id가 있으면 `SOURCE_EXISTS`다. 고칠 수 있는 것은 설명서(`sources/<id>.yaml`)뿐이고, 설명서를 바꾸면 그 자료를 쓴 노드가 "다시 확인 필요"가 된다.
- `reliability`: `low`·`medium`·`high`. `low` 자료에만 기댄 주장은 `sources.reliability`가 알린다.
- `spans`: `[{ id, quote }]` 인용 구간. 글 자료(.txt·.md)는 인용이 글에 있어야 한다. 글이 아닌 자료(PDF 등)는 엔진이 글을 읽지 않으니 **spans의 인용만** 근거로 쓸 수 있다.
- 노드가 자료를 쓰게 하려면 그 노드(또는 윗노드) 앞머리에 `sources: [id, ...]`를 적는다(작가가 파일을 고친다). 그러면 요청 payload의 `sources`에 설명과 spans가 실린다. 원본 글은 `folio_sources { op: 'get', id }`로 읽는다.

## 주장 잇기

1. **쓰는 중**: 추출 요청에 `evidence.wanted: true`가 있으면 답 JSON에 `claims`를 넣는다: `[{ "quote": 원고의 주장 문장, "sources": [{ "sourceId", "quote": 자료 인용 }] }]`. 받치는 자료가 없으면 `"sources": []`. 커밋이 끝나면 기록된다.
2. **커밋된 노드**: `folio_sources { root, op: 'link', nodeId, claims }`. 대조 대상은 지금 파일 본문이다. 한 노드의 새 목록이 앞 목록을 대신한다. 빈 목록은 "주장 없음"이다.
- 주장 인용은 원고(코드 블록 밖)에 그대로 한 번 있어야 한다. 여러 번 있으면 `before`·`after`로 좁힌다.
- 틀린 인용이 하나라도 있으면 아무것도 기록되지 않는다(`EVIDENCE_INVALID`, `details.errors`의 `index`·`link`·`code`). 추출 답이면 다시 묻는다.
- 자료에 없는 근거를 지어내지 않는다. 근거가 없으면 없다고 적고, 엔진의 참고 의견을 작가에게 보여 준다.

## 본문이 바뀐 뒤

- 엔진이 주장 인용 + 앞뒤 문맥으로 다시 찾는다(등장 위치와 같은 규칙). 못 찾은 것은 `folio_status`의 `evidence.stale`에 나온다(다른 "다시 확인 필요"와 한곳에서 본다. `folio_sources { op: 'list' }`의 `evidence`도 같은 값). 그 노드의 주장을 다시 `link`한다. `evidence` 기능이 꺼져 있으면 `evidence`는 `null`이다.
- `folio_sources { op: 'get', id }`의 `links`는 그 자료에 걸린 주장과 상태(`located`·`relocated`·`stale`), 연결마다 `verified`(지금 자료에 그 인용이 있는가)를 준다.

## 검사

| 검사 | 종류 | 알리는 것 |
|---|---|---|
| `sources.claim-supported` | 결정론 | 확인된 근거가 없는 주장(`CLAIM_UNSUPPORTED`) |
| `sources.numbers-match` | 결정론 | 주장의 숫자·연도가 연결된 자료 인용에 없음(`NUMBER_NOT_IN_SOURCE`) |
| `sources.reliability` | 결정론 | `low` 자료에만 기댄 주장(`LOW_RELIABILITY_ONLY`) |
| `sources.conflict` | 모델 | 연결된 자료끼리 어긋남 |
| `sources.claims-found` | 모델 | 주장으로 표시 안 된 사실 문장(원고 인용 필요) |

- 모두 참고 의견(advisory)으로 시작한다. 참고 의견으로 원고를 고치지 않는다.
- 작가가 원하면 `checks: { sources.claim-supported: { severity: block } }`처럼 올린다(`hard`는 안 된다). 그러면 넘기려면 작가의 이유가 필요하다.
- 세트를 빼거나 `mode: off`로 끄면 그 검사는 돌지 않는다. `core.promise-order`·원고 hash·영수증 잠금은 그대로다.

## 오류일 때

- `EVIDENCE_INVALID`: 주장 하나라도 틀려 아무것도 기록되지 않았다. `details.errors`마다 고쳐 다시 낸다(`CLAIM_QUOTE_NOT_FOUND`·`CLAIM_AMBIGUOUS`·`CLAIM_DUPLICATE`·`CLAIM_SOURCE_UNKNOWN`·`CLAIM_SOURCE_QUOTE_NOT_FOUND` 등).
- `SOURCE_EXISTS`·`SOURCE_IMMUTABLE`: 그 id(또는 원본 이름)가 이미 있다. 다른 id로 더하거나, 설명서만 고칠지 작가에게 묻는다.
- `SOURCE_PATH_INVALID`·`SOURCE_TOO_LARGE`: 경로가 절대 경로의 보통 파일이 아니거나(링크·폴더·없음) 너무 크다. 작가에게 알린다.
- `SOURCE_SPAN_NOT_FOUND`·`SOURCE_SPANS_INVALID`·`SOURCE_INPUT_INVALID`: 입력을 고쳐 다시 낸다. 아무것도 쓰이지 않았다.
- `SOURCE_NOT_FOUND`·`SOURCES_ARGS_INVALID`: id나 인자를 확인한다.
- `FEATURE_DISABLED`: 작가가 끈 기능이다. 켤지는 작가에게 묻는다.

/** MCP 너머의 가짜 호스트 모델. script: 노드 id → { draft, events, claims }. 검사는 지적 없이 답하고, 수정 요청에는 같은 원고를 돌려준다. */
function answerer(script = {}) {
  return (request) => {
    const p = request.payload;
    const own = script[p.node.id] ?? {};
    if (request.purpose === 'check') return JSON.stringify({ checked: p.checks.map((c) => c.checkId), findings: [] });
    if (request.purpose === 'revise' || request.purpose === 'user_revision') return p.draft;
    if (p.produces === 'plan') return `${p.node.title || p.node.id} 계획: 자료로 다룰 내용`;
    if (p.produces === 'children') return JSON.stringify({ children: [{ id: `${p.node.id}-1`, title: '첫 자식' }] });
    if (p.produces === 'draft') return own.draft ?? `${p.node.title || p.node.id} 본문.`;
    if (p.produces === 'events') return JSON.stringify({ events: own.events ?? [], appearances: [], mentions: [], ...(own.claims ? { claims: own.claims } : {}) });
    throw new Error(`no answer for ${request.purpose}/${p.produces}`);
  };
}

async function ok(promise) {
  const out = await promise;
  assert.equal(out.ok, true, JSON.stringify(out.error));
  return out.result;
}

/** until 을 만날 때까지 run/resume/decide(approve) 를 MCP 로 돌린다. 지나온 결과 이름과 요청을 모은다. */
async function drive(folio, root, start, answer, until = (o) => o.status === 'done') {
  const labels = [];
  const requests = [];
  let out = await ok(folio.call('folio_run', { root, ...start }));
  for (let i = 0; i < 60; i += 1) {
    labels.push(label(out));
    if (until(out)) return { labels, requests, out };
    if (out.status === 'needs_model') {
      requests.push(...out.requests);
      out = await ok(folio.call('folio_resume', { root, runId: out.runId, answers: Object.fromEntries(out.requests.map((r) => [r.requestId, answer(r)])) }));
    } else if (out.status === 'needs_user') {
      out = await ok(folio.call('folio_decide', { root, runId: out.runId, action: 'approve' }));
    } else throw new Error(`unexpected ${out.status}`);
  }
  throw new Error('drive did not finish');
}
