# Folio 제품 출시 전략 초안

최초 작성일: 2026-10-07. 제품 방향 갱신: 2026-10-08.
사업 가설과 출시 순서이며 매출 전망이나 신규 구현 승인서는 아니다.
기술 방향은 [범용 AI 작업 데이터 관리 설계](2026-10-08-general-ai-work-data-design.md),
구현 순서는 [이식 계획](2026-10-08-general-data-port-plan.md)에 둔다.

Folio는 여러 AI 도구로 작업하는 사람이 핵심 원본과 파생 결과물을 관리하는 독립 제품이다.
MCP는 호스트의 연결 방식이고 데이터 관리 기반은 판본·입력·결과·결정을 이어 주는 엔진이다.
사용자는 AI와 작업하면서 그 결과가 무엇을 기준으로 만들어졌는지 확인하고 다시 사용할 수 있다.

## 1 타깃과 제품의 구분

Folio의 대상은 문서·자료·자산을 여러 AI 작업에 재사용하는 사람이다.
소설은 적용 분야 중 하나이며 작가 전용 제품으로 제한하지 않는다.
Vibelore는 소셜 플랫폼 창작자용 제품이며 상세한 창작 하네스와 스킬을 갖춘다.
두 제품은 타깃·사용 경험·실행 절차를 따로 가진다.
Folio를 Vibelore의 하위 엔진으로 포지셔닝하지 않는다.

이전의 장편 작가 중심 초기 출시 가정은 이번 방향으로 대체한다.
초기 사용 검증은 여러 AI 도구를 오가며 동일한 자료의 판본과 결과를 실제로 관리하는 사람에게 집중한다.
브랜드 자료에서 안내문·번역·이미지를 만드는 작업과 연구 자료에서 보고서·표를 만드는 작업을
후보로 비교한다. 사용 빈도·관리 비용·지원 부담을 확인한 뒤 첫 온보딩 사례를 선택한다.
처음부터 모든 업무의 완성도와 모든 도구의 공식 지원을 약속하지 않는다.

## 2 사용자에게 제공할 가치

> 원본을 한 번 관리하고, 어떤 AI 도구로 만든 결과든
> 사용한 판본과 함께 연결해 확인하고 다시 작업할 수 있다.

핵심 원본과 표현 조건을 분리하면 언어·스타일·형식별 결과를 나란히 관리할 수 있다.
원본을 바꾼 뒤 영향을 받는 결과를 찾고, 과거 결과가 사용한 자료를 확인하는 경험이 제품의 중심이다.
등록과 이력 조회만큼 실제 수정·재작업과 백업·내보내기까지 끝내는 것이 중요하다.

모델은 분야별 구조와 작업을 제안한다. Folio는 요청·응답·입력 판본·파일·검토·선택을 관리한다.
각 분야에 전용 에이전트와 세밀한 하네스를 먼저 만들기보다 공통 계약과 작은 예제를 제공한다.
사용자가 원하면 집필처럼 상세한 팩을 선택할 수 있다.

## 3 MCP와 저장 기반의 관계

| 구성 | 사용 가치 | 필요한 투자 |
|---|---|---|
| MCP와 현재 엔진 | 호스트를 통한 작업·기록 검증 | 실제 호스트 연결·재개·지원 범위 확인 |
| MCP와 범용 로컬 데이터 기반 | 원본·입력·변형 결과의 지속적인 관리 | 불변 판본·봉인 입력·파생 관계·조회·복구 |
| 같은 데이터의 관리 화면 | 원본·결과 비교와 변경 영향 확인 | 범용 조회 화면·파일 상태·근거 이동 |
| 관리형 공유 서비스 | 기기·팀 간 공동 관리 | 실제 수요 이후 계정·권한·동기화·서버 운영 |

MCP와 데이터베이스는 함께 사용할 수 있다. 공통 데이터 기반을 먼저 만들고,
같은 조회를 MCP와 화면에서 사용한다. 중앙 관리를 위해 초기부터 클라우드가 필요한 것은 아니다.
생성은 호스트가 담당하고 데이터는 호스트를 바꿔도 보존되도록 만든다.
호스트 중립 계약과 실제 공식 지원 범위는 구분한다.

## 4 첫 사용 경험

1. 사용자가 핵심 자료를 등록하고 AI와 관리할 항목을 정한다.
2. 같은 원본 판본으로 텍스트 작업과 이미지 연결 작업을 수행한다.
3. 각 결과에서 사용한 원본·표현 조건·검토·선택 상태를 확인한다.
4. 원본을 바꾸고 영향받는 결과를 확인해 필요한 작업만 새 입력으로 다시 수행한다.
5. 이전 입력과 결과를 비교하고 백업·복구·내보내기한다.

실행 기반을 검증하는 첫 합성 사례와 실제 고객의 첫 판매 사례는 구분한다.
새 검색·위키·벡터 기능은 이 작업의 조회 문제를 해결하는 순서로 추가한다.
Folio 자체의 모델 제공이나 소셜 커뮤니티 운영은 이 작업의 필수 조건이 아니다.

## 5 사업상 이득과 검증

| 가치 가설 | 확인할 증거 |
|---|---|
| AI 도구가 달라도 원본과 결과가 이어짐 | 서로 다른 호스트에서 판본·결과 재사용 성공 |
| 중복 자료와 서로 다른 사양으로 작업하는 실수 감소 | 현재 방식 대비 자료 찾기·오입력·수정 시간 |
| 원본 변경 후 필요한 결과를 찾아 재작업 | 자발적인 두 번째 수정 작업과 영향 조회 사용 |
| 과거 입력과 선택 근거를 보존 | 인수인계·복구·결과 비교를 실제로 완료 |
| 상세한 하네스 없이 새로운 작업을 구성 | 개발자 개입 없이 지원 계약 안에서 파이프라인 추가 |

범용성은 확장 구조의 목표다. 초기 고객의 구체적인 문제와 지불 의사는 별도로 검증한다.
기능 수나 DB 종류를 늘린 것만으로 경쟁력·결제·재사용을 증명하지 않는다.
경쟁 우위 후보는 호스트 전환, 정확한 이력, 복구 신뢰, 작은 시작 절차와 관리 화면의 사용성이다.
경쟁 제품에 이 기능이 없다고 가정하지 않고 실제 작업 단위로 비교한다.

## 6 배포와 유료화 가설

공개 기반 엔진·MCP와 유료 관리 경험을 병행하는 모델을 검토한다.
유료 후보는 쉬운 자료 등록, 원본·변형 비교 화면, 영향 조회, 업데이트·복구·지원이다.
데이터 무결성은 무료 기반에서도 유지한다. 사용자 데이터의 내보내기를 막아 잔류시키지 않는다.
기존 라이선스·기여 권리를 유지하고 추가 제품의 배포 구분은 별도로 확정한다.

모델·도구 이용료는 사용자가 선택한 호스트의 비용으로 구분한다.
관리형 생성이나 공유 서비스를 제공할 때는 실행·재시도·갱신·저장·지원 비용을 측정한 뒤 과금한다.
첫 가격은 실제 작업 이득과 지원 시간에 맞춰 유료 파일럿에서 시험한다.
작가용 월 구독 가격 가정을 범용 제품에 그대로 적용하지 않는다.

## 7 투자 순서와 프로덕션 조건

먼저 범용 자원·입력·결과 계약을 두 실제 작업 형태에서 검증하고 기존 집필 기능을 유지한다.
다음으로 실제 호스트에서 원본 보존·참조 반영·중단 재개·호스트 전환을 평가한다.
사용자 도움 없이 자료 등록·조회·복구를 끝내는 작은 화면을 붙여 유료 작업을 검증한다.
공유 서비스는 반복되는 공동 관리 요구와 비용을 확인한 뒤 투자한다.

현재 합성 909개 테스트는 기존 구현 계약과 무결성의 근거다.
신규 범용 실행 계약·실제 생성 품질·수요·지원 환경 전체를 검증했다는 뜻은 아니다.
원격 CI, 지원 환경의 설치·업데이트·재연결·복구와 신규 계약의 수용 시험이 필요하다.
실제 사용자 자료·생성 결과는 저장소 테스트 데이터로 커밋하지 않는다.

참조 ID만 있는 파일과 bytes를 보관한 파일, AI 보고와 Folio가 검증한 사실,
후보와 채택 결과, 현재 원본과 과거 고정 입력을 화면에서도 구분한다.
Folio의 성공 기준은 여러 AI 도구를 쓰는 사람이 자료와 결과를 관리하는 시간을 줄이고,
필요할 때 입력과 결과를 신뢰할 수 있게 다시 확인하는 것이다.
