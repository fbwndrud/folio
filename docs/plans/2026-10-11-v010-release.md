# Folio 0.1.0 공개 계획

사용자가 전체 사전 점검·README 비교/문체 보완 후 자기 GitHub 계정에 공개 저장소와 0.1 릴리스를 요청했다. 연결된 계정은 `fbwndrud`, 신규 저장소는 `folio`, 버전은 `0.1.0`으로 정한다. GitHub 릴리스가 범위이며 npm registry 게시를 포함하지 않는다.

## 순서

1. 직전 준비 커밋 `e7516d1`과 현재 변경/추가 파일을 기준으로 독립 Standards/Spec 검토를 실행한다. 이슈 트래커 대신 저장소 지침과 구현 계획·사용자 동작을 정본으로 사용한다. 위험한 기존 경계도 함께 조사한다.
2. 공식 OSS README 4종과 사용자 진입 흐름을 비교한다. 설치·첫 실행·도구 연결·화면·내보내기·한계 순서로 간결한 한국어/영어 README를 작성한다.
3. 재현 가능한 지적을 수정한다. 우선 정적 번들 라이선스, 예시 실패 정리의 파일 보존, canonical 출력 경계를 보완한다. 독립 재검토와 회귀 테스트로 확인한다.
4. 코드 Apache-2.0 유지. 제작 예시 원고·이미지·조사 노트의 권리를 CC0-1.0으로 공개하되, 인용된 제3자 자료·브랜드·소프트웨어는 제외한다. Studio의 제3자 라이선스와 ELK 원본 제공 정보를 배포물에 넣는다.
5. package/lock/viewer의 버전을 0.1.0으로 맞춘다. 생성 결과물과 개인 경로를 공개 Git에 넣지 않는다. 엔진 tarball·예시 5 ZIP·예시 웹 모음·checksum·릴리스 설명을 별도 산출물로 만든다.
6. lint/typecheck/backend/viewer/설치 검증·dependency audit를 실행한다. 다운로드한 실제 릴리스 사본의 checksum·이미지·Studio·원본 기록장을 검증한다.
7. 검증한 소스 스냅샷으로 사용자 계정의 공개 저장소를 생성한다. CI가 성공한 같은 커밋을 v0.1.0으로 태그하고 릴리스한다. 링크·첨부 파일을 외부에서 다시 확인한다.

## 완료 조건

- Critical/High 재현 결함 수정 및 독립 재검증.
- README의 명령을 새 설치본에서 실제 실행할 수 있고 지원 언어·알파 한계가 일치.
- 공개 소스와 설치본의 문서 링크가 열림.
- 새 공개 소스에 작품·모델 가중치·비밀 값·로컬 경로 없음.
- 정적 번들과 예시의 라이선스/고지/원본 제공 링크 포함.
- 공개 GitHub 저장소·CI·v0.1.0 릴리스·실제 다운로드 검증 완료.

## 복구

기존 작품 기록장·실제 작가 승인을 변경하지 않는다. 예시 빌드가 실패하면 부분 출력은 보존하여 소유하지 않은 파일을 삭제하지 않는다. 기존 출력은 덮어쓰지 않는다. 공개 저장소는 검증한 소스 스냅샷으로 시작하며 개발용 저장소의 이력을 손수정하지 않는다. 릴리스 결함이 발견되면 게시 상태를 정직하게 보고하고 새 패치 판본으로 수정한다.
