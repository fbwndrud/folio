# Studio 세 모드 구현

사용자 결정: 2026-10-09, 세 시안을 모두 원고·검토·출판 모드로 실제 반영한다.
정본은 기존 설계이며 `2026-10-09-studio-design-proposal.md`의 검증된 화면 방향을 따른다.
시안의 합성 원고·하드코딩·비교 switcher는 제품 코드에 옮기지 않는다.
생성물이 포함된 시안은 사용자 규칙에 따라 ignored 디렉터리에 보존한다.

## 순서와 완료 조건

1. 읽기 모델: 공개 tracking query와 활성 영수증을 재사용한다. 근거의 본문 hash,
   적용 기준·범위·관점·self-review와 coverage를 노출한다. live/snapshot 모양이 같다.
2. 원고: 기존 텍스트·그림·읽기 설정·검토 기록을 유지하며 대상별 추적 패널을 추가한다.
   기록 클릭은 원문으로 이동하고 hash가 일치할 때만 인용을 강조한다.
3. 검토: 사용자 정의 대상·기준의 전체 기록과 원문, 장별 참조 연결을 제공한다.
   믿음·추론·시점·경로를 유지하고 같은 위치의 상충 기록을 하나로 합치지 않는다.
4. 출판: 실제 저장 본문의 읽기 미리보기, 계층형 목차, Web ZIP·EPUB 다운로드를 제공한다.
   download는 인증된 읽기 작업이고 작품·기록장·서버 임의 경로에 쓰지 않는다.
5. 회귀·브라우저 검증: 합성 fixture 계약 테스트, 기존 전체 check, viewer tests/build,
   실제 중편과 안내서에서 세 모드·정적 사본·좁은 화면을 확인한다.

## 호환·롤백

새 조회 필드와 경로는 추가 방식이다. 이전 snapshot에 추적/출판 필드가 없으면
미포함을 안내하고 원고는 계속 읽는다. resource-only 작업의 Library는 유지한다.
읽기 화면은 기존 route를 유지한다. 다운로드와 미리보기는 작가 승인으로 취급하지 않는다.
rollback은 읽기 모델·화면·export 렌더러를 되돌리며 작품 데이터나 ledger를 수정하지 않는다.
고정 hash·영수증·hard 차단·append-only·자기검토·soft 비자동수정 규칙은 유지한다.

## 검증할 위험

- 원고 변경 뒤 옛 근거 강조, pending coverage를 현재 사실로 표시하는 오류.
- unordered 작업, 다른 인물 관점·분기 경로·작품 내 시점을 임의로 합치는 오류.
- 일반 문서에도 소설 전용 대상·기준·장 구조를 강제하는 오류.
- EPUB 부모 계획 메모의 본문 혼입, 순서·원문 hash·링크 손실.
- 정적 내보내기에서 live API나 쓰기 버튼으로 연결되는 오류.
- 다운로드 API의 경로 주입·인증 우회·출력 한도와 오류 처리.

독립 사용자 사용성 검사와 다양한 실제 EPUB reader 검증은 별도 검증 과제다.
