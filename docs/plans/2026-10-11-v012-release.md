# 0.1.2 패치 배포

사용자 승인: 수정 코드를 GitHub에 반영하고 수정한 패키지를 배포한다. 기존0.1.0/0.1.1 자산은 보존하며 CI는 추가하지 않는다.

1. root/viewer manifest 및 lock을0.1.2로 맞추고 설치·재연결 안내를 새 GitHub tarball URL로 갱신한다. 예시 ZIP과 스크린샷 링크는 원래0.1.1 주소를 유지한다.
2. 버그 수정의 전체1774/70 회귀 결과를 바탕으로 새 버전의 MCP identity/schema/첫 실행 및 tarball 새 설치를 검증한다. 배포 전에 모든 코드 변경을 커밋하고 준비된 화면과 함께 패키징한다.
3. tarball의 manifest/runtime/document bytes를 커밋과 비교하고 SHA256SUMS를 만든다. main에 일반 fast-forward push한 뒤 새v0.1.2 태그와 draft prerelease에 패키지/체크섬을 올린다. 이전 릴리스를 덮어쓰지 않는다.
4. 자산 크기·GitHub digest를 확인하고 릴리스를 공개한다. 공개 다운로드 bytes/hash와 빈 npm cache의 실제 npx MCP 연결·영어 원고 생성·기본 Studio Web/EPUB 태그를 검증한다. 모의 승인은 합성 작품에서만 쓴다.
5. 공개 결과와 재접속 안내를 보고한다. 실패하면 새 릴리스를 draft로 유지하거나 되돌리고 이전 패키지 URL을 사용한다. 기존 작품을 변환하지 않는다.
