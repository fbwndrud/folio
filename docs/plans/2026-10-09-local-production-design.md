# Folio 로컬 출시 설계

사용자 승인: 2026-10-09 “좋아 이어서 작업해. production level 까지 ㄱ”.
앞서 제시한 화면·데이터 통합과 처음 사용자 흐름을 구현하고 검증한다.
클라우드·협업은 현재 확정되지 않았으므로 기본 출시 대상은 개인의 로컬 MCP와 화면이다.
이는 이름이나 테스트 개수로 production을 선언하는 계획이 아니다.

## 목표와 완료 계약

1. `main@713b9d8`의 뷰어·판본·이미지·웹/EPUB 내보내기와
   `codex/dynamic-tracking@c44b13c`의 추적·원본·입력·실행·조회·벡터가 한 설치에서 동작한다.
2. 원고 작성→합성 그림 등록→검토·작가 채택→화면 확인→웹/EPUB 내보내기를
   실제 stdio MCP와 로컬 HTTP에서 확인한다. 테스트의 사용자 결정은 합성 사본에서만 한다.
3. 새 데이터의 원본·결과·버전·근거·최신성·재검토 필요가 관리 화면에서 보인다.
4. 새 설치, 기존 작품, 중단·재연결, 백업·상태 진단, export 뒤 read-only 동작을 검증한다.
5. 지원 OS/Node CI 설정, 로컬 실측·보안·검증 결과와 미검증 항목을 구분하여 기록한다.
   원격 저장소가 없으므로 원격 CI 통과·게시 완료를 가정하지 않는다.

## 통합 방법

기존 managed worktree를 재사용하되 `codex/production-ready`에서만 변경한다.
`main`, 직전 구현 브랜치, 원래 dirty checkout과 Vibelore는 유지한다.
선별 재작성·대규모 구조 변경보다 두 이력을 merge하고 경계별 충돌을 해소한다.
merge commit은 두 부모를 남긴다. 오래된 문서를 현재 계약으로 취급하지 않는다.

보존할 경계:
- core는 모델·네트워크를 부르지 않는다. 임베딩은 선택 adapter에만 있다.
- 기존 집필·그림·판본 규칙과 새 Resource 경로는 각각 읽기 호환을 유지한다.
- 원고·그림·자원 승인과 화면·내보내기는 서로의 승인을 대신하지 않는다.
- hash, 영수증, hard 차단, append-only, 자기검토 표기, soft 비자동수정은 해제 불가다.
- 신규 MCP도 main의 입력/출력 스키마·structuredContent 계약과 양립한다.

## 화면의 새 데이터 보기

기존 Library에 원본·결과 화면을 추가한다. viewer 서버를 시작할 때 정한 작품 root만
사용하고 HTTP 요청에서 root/path를 받지 않는다. 같은 token·Origin·Host 검증을 따른다.
화면은 목록·정확한 판본·근거·미완료 원인을 읽는다. 모델 실행·위임·원본 선택·승인은
기존 MCP 호스트 흐름으로 진행한다. 모델 설치가 없어도 화면과 집필은 동작한다.

`GET /api/resources`와 `GET /api/resources/:revisionId`를 추가한다.
목록은 검증된 metadata generation에서 선택 원본/최종 승인 결과만 읽는다.
generation이 없거나 낡았으면 빈 상태/낡음/원인 표시이며 current를 만들었다고 쓰지 않는다.
한 번도 정식 선택/승인하지 않은 후보를 revisionId만 안다고 HTTP에서 읽을 수 없게 한다.
과거 정식 선택/승인 판본은 stale checkpoint의 역사 근거로 읽을 수 있다. selectionCurrent로 현재 원본 선택 여부를 구분하며 과거 선택을 현재 선택으로 표시하지 않는다.
손상은 오류로 표시하고 실제 bytes·영수증 무결성 검증을 생략하지 않는다.
Resource-only workspace도 소설 설정 없이 화면을 연다. 검증된 Folio 관리 자료가 없는 임의 폴더를 탐색하지 않는다. writing/resource 모드와 화면 능력을 구분한다.
읽기 API는 work lock·recovery·cache 생성이 없는 pure read를 사용한다. 읽기 전후 체크포인트가 바뀌면 재시도 오류를 제공한다.
본문 미리보기는 text/JSON만 escaped text로 제공한다. 이미지·음성·영상은 파일 상세와
hash/타입을 표시하고 이번 단계에 새 임의 파일 제공 API를 만들지 않는다.
외부 URI를 자동 열거나 fetch하지 않는다. 오래된 generation은 실제 체크포인트를 표시한다.

정적 검토 화면 export에 새 목록과 허용된 text/JSON 판본 보기를 포함한다.
export 자체가 원본 선택·새 승인·검색 갱신을 만들지 않는다. 기존 export도 읽기 호환한다.

## 사용자가 이해할 흐름

설치 안내는 실제 지원 명령과 연결용 스킬, 첫 작품 예시, 원고/그림/검토/내보내기
완료의 차이를 설명한다. 기존 인터뷰·명시적 위임을 유지한다.
화면은 비어 있음·후보만 있음·자료 변경·미검토·오류·외부 미관측을 구분한다.
기술 ID·hash·checkpoint는 기본 요약에서 숨기고 펼친 상세에서 볼 수 있다.

## 운영과 출시 품질

read-only doctor는 작품 상태·기록장·관리 파일/자원 검증과 필요한 후속 행동을 출력한다.
손상을 자동으로 고치거나 ledger를 다시 쓰지 않는다. 열린 작업은 진단과 복구를 구분한다.
백업·복원은 문서와 합성 복원 시험으로 검증한다. 백업은 작품 폴더 전체가 단위다.

tarball은 빌드된 화면과 MCP/CLI를 포함하고 설치본에 개발 의존성을 요구하지 않는다.
소스 checkout은 setup으로 준비한다. 모델 가중치·Python 런타임은 선택 설치이며 패키지에 넣지 않는다.
성능은 합성 작품 규모·환경·시간/크기를 실제 기록하고 내부 오류 없는 종료를 검사한다.
숫자는 벤치마크 근거이지 전체 사용자 SLA가 아니다. 모델 추론 속도는 별도다.
임베딩 입력은 개별8MiB·100개와 합산32MiB 상한을 모두 따른다. profile에 이 정책을 기록한다.
정적 export 교체 실패는 이전 출력의 복구 가능성을 보존한다. SDK는 patched1.x를 배포한다.

## 이행·롤백

새 정본 포맷으로 기존 원고를 강제 변환하지 않는다. 새 metadata는 명시 refresh로 생성한다.
임시 index 재구성은 이전 안전한 교체 계약을 유지한다. 원본/ledger 백업을 먼저 권장한다.
미완료 작업이 있는 업그레이드는 exact 옛 영수증·입력·권한을 재검증하며 새 승인으로 둔갑하지 않는다.
이상 시 출시 브랜치를 직전 버전으로 되돌리는 대신 별도 checkout에서 전체 백업 사본을 연다.
새 코드가 쓴 데이터에 구버전 writer를 동시에 연결하지 않는다.
