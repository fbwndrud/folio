# 중편과 기존 초보자 실습책: 실행 결과

2026-10-09. 실행 계획: [수용 테스트 계획](2026-10-09-novella-and-handbook-test.md).
기존 작업 사본 `codex/production-ready`에서 실행했다. 원래 Folio 체크아웃과
Vibelore는 수정하지 않았다. 작품·원고·실행 응답·스크린샷·내보낸 파일은
커밋하지 않는 `.local-output/novella-guide-20261009/`에 보관했다.

## 결론

중편 크기의 계층 집필에서 실제 저장 오류를 발견하고 수정했다.
수정 후 본문 저장·추적 보충·재검토·재연결·내보내기가 통과했다.
기존 실습책의 안내서 만들기·수정 요청·채택·다시 읽기·전체 백업 복원도 통과했다.
그러나 추적 관찰 표시, 큰 관계도 탐색, 출판 목차와 구버전 실습책은 보완이 필요하다.
이번 결과를 모든 장르·장편·자동 추출 품질 또는 초보자 성공률의 증명으로 해석하지 않는다.

## 실행 방법과 검증 경계

- 실제 공개 stdio MCP: `folio_init`, `folio_structure`, `folio_run`, `folio_resume`,
  `folio_decide`, `folio_find`, `folio_tracking`, `folio_sources`, `folio_export`, `folio_view`.
- 새 합성 작품만 사용했다. 모의 결정은 이 테스트 작품 안에만 기록했다.
- 이 세션의 AI가 새 중편 원고를 작성했다. 저장·추출·검사 응답은 로컬 호스트 스크립트로
  재생했다. 모델 검사 응답은 스크립트의 자기검토이며 독립 검토가 아니다.
- 추적 추출은 원고를 읽고 작성한 고정 응답이다. 별도 모델이 18장면에서 스스로 대상을
  발견하거나 의미를 정확히 추출하는지를 시험한 결과가 아니다.
- 현재 설치된 외부 Explain Like I'm Five 스킬은 찾지 못했다.
  실제로 읽은 기준은 Folio의 [내재화한 쉬운 설명 지침](../../skill/folio/references/plain-language.md)과
  2026-10-04의 기존 `folio-public-guide-20261004/book.md`다.
  그 실습책은 6장·12절이며, 이번에는 1·2·5·6장의 안내서 실습 경로를 따랐다.
- AI가 설명서를 따라가는 모의 실습이다. 독립된 실제 초보자 시험은 하지 않았다.
- 초기 대상 정의는 기존 엔티티 Markdown 인터페이스로 등록했다.
  추적 계획·발견·근거·승인·기록장·보충은 공개 도구를 사용했다. 내부 기록장은 수정하지 않았다.

## A. 중편: 파란 우편함의 여름

| 확인 | 실제 결과 |
| --- | --- |
| 규모 | 6장·18장면, 본문 26,721자·168문단. 권·장·장면 합계 25개 섹션 |
| 원고 저장 | 18개 본문이 작성 원고와 일치, 모두 채택 상태 |
| 뒤늦은 대상 발견 | 6번째 장면에서 관리 대상 추가. 파일 경로 없는 추적 대상 조회 확인 |
| 임시 보관자 | 서하→도윤→지연, 4개의 원문 근거 관찰. 임시 보관과 법적 소유·공개 허락을 구분 |
| 확정되지 않은 생각 | 인물에게 귀속된 관찰 1개와 관점 ID 유지. 확정 사실로 변환하지 않음 |
| 나중에 기준 추가 | 별도 모의 계획 결정 후 기존 부분의 보충 필요 발생 |
| 재검토와 보충 | 먼저 재검토만 실행해 미보충 목록이 그대로임을 확인 |
| 원문 유지 | 25개 섹션 보충 후 18개 본문의 hash 비교 일치 |
| 최종 범위 | 25개 섹션×4기준=100개 확인 범위, 모두 complete. 유효 관찰 24개 |
| 최종 상태 | 미보충·추적 재검토·stale·drift·flagged·warnings·waiting 모두 빈 목록. 기록장 무결성 정상 |
| 재연결 | 장면 7의 모델 응답 대기에서 동일 실행 ID·요청으로 재개. 초기 장 저장 오류 후에도 도구로 재개 |
| 내보내기 | 웹·EPUB 18개 본문 모두 저장본과 일치. ZIP CRC·XML 정상. 검토 사본 API 호출 0 |

`complete`는 현재 기준과 본문에 대해 호스트가 확인했다고 기록한 상태다.
100% 완성도, 관찰 누락 없음, 의미 이해의 정확도 또는 문학성 점수가 아니다.
중편의 장면 12에서 사용자 질문 재연결을 검사하려던 스크립트 조건은 잘못되어 실행되지 않았다.
그 경계는 아래 안내서의 실제 승인 질문으로 따로 검사했다.

별도 고정 색상 합성 사본에서는 빨강이라는 explicit 관찰 답이 재시도 끝에
승인 불가 질문으로 막혔다. `approve`를 직접 호출해도 거부됐으며 잘못된 관찰과
원고는 활성화·채택되지 않았다. 고정 값 충돌 검사를 사용자 결정으로 우회하지 않았다.

이번 안내서는 기본 knowledge 검사와 스크립트 검사 응답을 사용했고, 인용 연결을 실제로
검증했다. 원문 근거 연결을 AI가 자유롭게 발굴하는 능력이나 sources 전 검사 세트의
정확도를 이 실습에서 평가하지 않았다.

### N1 근거와 수정 범위

[소설 팩](../../packs/novel/pack.yaml)의 branch 파이프라인은 계획·자식 생성·검토·저장을
진행하고 본문 사건 추출을 하지 않는다. 반면 [기존 저장 경계](https://github.com/fbwndrud/folio/blob/v0.1.0/core/tracking/commit.js#L52)는
추적 계획이 있으면 모든 새 원본 저장에 추적 batch를 요구했다.

장면 2개+부모 장 1개로 축소한 회귀 테스트에서도 정확히 같은 오류가 발생했다.
[수정](https://github.com/fbwndrud/folio/blob/v0.1.0/core/tracking/commit.js#L54)은 branch 계획 저장에 본문 batch를 요구하지 않는다.
leaf 본문은 계속 batch를 요구하며, branch라도 후보 snapshot이 있으면 전체 batch가 필요하다.
본문 hash·영수증·판정 대조·hard 차단·후보 binding은 기존대로 유지한다.

[회귀 테스트](../../test/run/tracking-container.test.js)는 자식 장면 채택→부모 장 채택→
부모 계획의 명시적 기록 보충까지 확인한다. 전체 범위 `all`은 계획 섹션도 포함하므로,
branch를 채택했다고 검사되지 않은 추적 범위를 완료라고 표시하지 않는다.
leaf의 누락 batch와 branch의 근거 없는 candidate snapshot 거부도 검사한다.

데이터 포맷과 기존 기록장은 바꾸지 않았다. 별도 데이터 마이그레이션은 없다.
코드 롤백은 이 조건 변경을 되돌리는 것이며, 기존 기록을 삭제할 필요는 없다.
롤백하면 활성 계획 아래 새 branch 저장은 다시 실패한다.

### UI·출판 근거

- [대상 조회](https://github.com/fbwndrud/folio/blob/v0.1.0/core/view/entity-view.js#L72)는 entity/usages/events/ledgers/promise/assets를 반환하며
  추적 observations를 반환하지 않는다. 편지함의 사건 0개는 관찰 0개라는 뜻이 아니다.
- [관계도](https://github.com/fbwndrud/folio/blob/v0.1.0/viewer/src/screens/Graph.jsx#L57)의 종류별 컨트롤은 색상 선택이다.
  전체 연결을 줄이는 필터가 아니다. 화면 실측과 스크린샷으로 밀집 상태를 확인했다.
- [출판 원본 선택](https://github.com/fbwndrud/folio/blob/v0.1.0/core/export/source.js#L22)은 leaf만 고르고
  [목차 렌더링](https://github.com/fbwndrud/folio/blob/v0.1.0/core/export/render.js#L67)은 그 목록만 나열한다.
- 기존 실습책 `book.md:339`의 EPUB·지면 미지원 문장은 구버전 설명이다.
  현재 PDF는 직접 생성 도구가 아닌 브라우저 인쇄, EPUB·웹·수동 지면은 지원한다.
  [현행 첫 작품 안내](https://github.com/fbwndrud/folio/blob/v0.1.0/docs/writing-guide.md#L55)에 실습·자료 연결 구분·실제 화면 한계를 보완했다.

## 검사 결과

- `npm run check`: lint·typecheck 성공, **1715/1715 테스트 통과**. 새 회귀 테스트 2개 포함.
- 수정 직후 관련 저장/후보 잠금 테스트 17개 통과. 이후 전체 검사에서 확대 검증.
- 실제 브라우저: 18장면 API 읽기, 마지막 장면, 서하 사건 이력 18개,
  대상 화면, 관계도, 자료 화면, 웹 책·EPUB 다운로드, 검토 사본 확인.
- 모바일 폭 390/736px: 갤러리·두 원고 화면 가로 넘침 없음. 브라우저 실행 오류 0.
- EPUB 두 개: ZIP CRC, 컨테이너·OPF·본문·목차 XML 정상. 중편 제목·본문 18개 정확히 일치.
- 생성 결과는 ignored output에만 두었다. 제품 코드 변경 1곳, lint 설정 1곳,
  사람용 문서와 계획·결과 문서, 합성 회귀 테스트만 변경했다.

실습 호스트의 중편 도구 호출은 600회(추가 조회·오류 재시도 포함), 성공 호출 중앙값 194ms,
최대 요청 payload 48,700bytes였다. 디버깅 중단·스크립트 검사·로컬 환경을 포함하므로
모델 실행 시간, 비용, 운영 SLA나 장편 성능으로 일반화할 수 없다.

## 다음 우선순위

1. 대상 화면에서 추적 기준별 관찰·근거·판본·explicit/attributed/inferred를 구분해 보여 준다.
   현재 값 하나로 임의 압축하지 않고 작품 순서·미확인 범위·관점을 함께 표시한다.
2. 관계도에서 장·대상·종류 선택, 선택 주변만 보기, 확대 후 읽을 수 있는 라벨을 제공한다.
3. 출판 목차의 권·장·절 계층을 보존한다. 부모의 내부 기획 본문을 출판 본문에 넣지 않는다.
4. 기존 실습책의 배포 읽기본을 현행 안내와 함께 재발행하고 독립된 첫 사용자 시험을 한다.
5. 별도 모델에 미리 답을 주지 않는 중편 추출 시험과 더 긴 작품·상충 자료 시험을 추가한다.

이번 작업에서 N3–N5의 UI/출판 기능을 구현했다고 주장하지 않는다.
실습 결과표는 공개 조회 응답을 모아 만든 별도 HTML이며 Folio 기본 Studio 기능이 아니다.
