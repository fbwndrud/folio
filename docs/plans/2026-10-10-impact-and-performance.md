# 변경 영향 및 중·장편 성능 개선

사용자 승인 범위: 변경 영향 화면과 중·장편 성능 개선을 먼저 구현하고 합성 데이터로 검증한다. 통합 검색·온보딩·자동 Wiki는 이후 단계다.

## 계약과 단계

1. 현재 stale/drift/recheck/flagged, tracking coverage 및 Resource freshness를 읽기 전용으로 모은다. 기준 버전과 현재 버전, 영향받은 구간, 검토 화면을 연결한다. 기록에 없는 의미적 관계를 추정하지 않는다.
2. `/api/impact`, Review의 Changes 화면, 정적 snapshot에 같은 정보를 제공한다. 상태/기록 검증 실패는 unknown/unavailable로 표시한다. 자동 승인·재작성·ledger 변경은 없다. 판본 상태는 main과 구분한다.
3. snapshot 내부에서 Work·검토 상태·근거 읽기를 한 번만 계산하고 구간 화면에서 공유한다. 요청 간 영속 캐시는 도입하지 않는다. 완료 전 원본·설정·관계 자료·기록장 버전을 재확인하여 변화 시 내보내기를 거부한다. 기존 응답 형식과 자산 버전 검증을 유지한다.
4. 합성 수정 → 변경 이유/버전 → 영향 구간 → 재검토 확인, 변조 fail-closed, API 인증, 정적 호환성을 검사한다. 동일한 합성 100구간으로 전후 시간을 측정하고 원문 hash/응답 형식을 비교한다. 전체 검사, viewer 검사와 build, 브라우저 모바일/데스크톱을 확인한다.
5. 최신 패키지 build/verify와 로컬 새 설치 검증을 실행한다. 원격 CI는 remote/권한의 실제 상태를 확인하고 미실행은 명시한다.

## 이전·롤백·완료

저장 포맷과 기존 MCP 도구는 변경하지 않는다. snapshot은 version 1에 optional impact 필드를 추가한다. 이전 정적 내보내기는 Changes가 제공되지 않는다고 안내한다. 신규 읽기 필드/화면 및 snapshot 내부 공유를 제거하면 기존 흐름으로 돌아간다. 롤백 중 사용자 원본과 승인 기록을 수정하지 않는다.

완료 조건: 기존 잠금 규칙 회귀 없음, 영향 이유와 실제 검토 기록 일치, 훼손된 기록을 정상으로 표시하지 않음, snapshot 결과 일치와 동시 변경 거부, 합성 100구간 실측 개선, 화면/내보내기/새 설치 검증 및 미확인 출시 과제 기록.
