# Studio 전체 화면·데이터 표시 재점검 결과

## 판정과 책임

이전 보고는 주요 신규 화면의 기능 검사를 전체 화면의 디자인 완성처럼 설명했다.
이는 부정확했다. 실제로 기존 Library와 Story threads의 상세·긴 제목·빈 상태를 충분히
검사하지 못했다. 이번 검사는 담당 에이전트의 직접 검사이며 독립 UX 평가가 아니다.

이번 결과는 아래 화면과 합성 데이터에서 확인한 수정이다. 모든 가능한 입력, 모든
장르, 실사용자의 이해도 또는 최선의 디자인을 보증하는 보고가 아니다.

## 발견한 문제와 수정

| 문제 | 확인과 수정 |
| --- | --- |
| JSON 객체 덤프 | Resource 목록/checkpoint/evidence, 사건, 변경 전후 버전을 항목명/값으로 표시. 완전한 JSON 자료도 항목으로 표시 |
| 사용자 속성 누락 | Definition details에서 사용자 정의 필드를 재귀적으로 보존. 0/false/null/빈 값 검사 |
| 같은 키 이름에 잘못된 의미 부여 | custom unknown을 Unobserved resources로 바꾸던 문제 수정. 시스템 metadata와 사용자 필드의 label 계약 분리 |
| Story threads 제목 겹침 | SVG 고정 좌표를 제거. 전개 카드 기본, 긴 제목이 줄바꿈되는 구간 테이블 선택 |
| 상위 그룹 사건의 위치 오해 | Group note와 실제 본문 사건 구분. 그룹 사건을 첫 잎 구간의 사건으로 그리지 않음 |
| 진행 기준 오표기 | 마지막 확정 구간/작성 구간을 상태에 따라 구분 |
| 전체 연결도의 작은 글씨 | 실제 연결 목록 기본, 선택한 정의의 도표만 표시. 모바일 세로 배치, 14px 글자 유지 |
| 빈 표·긴 색인 | 내용이 있는 탭을 먼저 표시, 색인 검색/접기, 빈 상태에 다음 행동 제공 |
| 각주와 참조의 내부 표기 | core parser가 만든 구간 조각으로 자료 제목 링크 표시. 참조 문제는 쉬운 문장과 원문 위치로 안내 |
| 이름 대신 ID | 정의/자료 사용처, 인용 위치, 검토 기록의 탐색 링크에 현재 이름 사용. 당시 버전 fingerprint 보존 |
| 설정 항목의 붙은 배치 | 항목·종류·선택지/Required를 정렬한 카드형 단계 목록 |
| 모바일 검사 그룹 잘림 | 표를 검색 가능한 카드로 교체. 선택 여부/추천/검사 영향/잠금 상태를 각각 명시 |
| 화면 오류의 내부 메시지 노출 | 쉬운 안내와 Reload viewer 제공, 원래 메시지는 접힌 상세에 보존 |

## 직접 확인한 범위

| 화면 종류 | 데이터/상태와 확인 |
| --- | --- |
| Overview | 18개 작성·확정 구간, 빈 작품의 작성 시작 안내 |
| Reader | 중편 18개 구간의 화면 본문을 원문과 대조: 전부 일치. 설명서 본문/근거, text/images 전환, SVG 100×100 로드 |
| Story threads | 중편의 실제 도입·해소 위치, 긴 제목 6구간/3스레드, 휴면, 도입 전 해소 hard 문제, Group note/타임라인 구분 |
| Evidence desk | 중편 19개 대상 기록의 필터/인용/원문, Reader 추적/Section review, 계획이 없는 작품의 빈 상태 |
| Changes | 변경 없는 원본과 변경 사례의 목록/이전 값/현재 값. 최신성은 별도 안내 |
| Review records/Receipt | 중편 18개 구간의 검토 상세를 모두 펼침. 단계/자기검토/참조/버전 표시, JSON 덤프 없음 |
| Check groups | 실제 선택/기본 추천과 고정 검사, 모바일 카드, custom 추천 이유/experimental/hard 회귀 검사 |
| Publish | 중편 계층형 목차/구간 미리보기/다운로드 안내, 빈 작품에 작성 시작 안내 |
| Resources/Resource | 선택 source와 승인 output, evidence/checkpoint 상세, JSON 0/false/null/배열/중첩 값, 잘린 JSON 원문 보존 |
| Sources/Source | 안내서 7개 주장과 1개 원문 자료 연결, 중복된 구간 링크 정리, 자료 제목과 원문 인용 |
| Figures & references | 합성 anchor 9/ref 6/footnote 2/bibliography 2/index 4, 6종 참조 문제, 탭별 표시와 출처 위치 |
| Connections | 실제/선언된 연결만 포함, 검색/정의 선택/도표, 모바일 4개 노드 전체 제목이 canvas 안에 배치됨 |
| Entity | 중편 17개 정의를 각각 열어 이름 확인. 합성 중첩 속성과 사건 상세, 자료/정의 사용처, 손상 ledger의 사건 숨김 |
| Settings | Reading settings, required 잠금 유지, 단계별 레이아웃. 원본 단계/승인 설정을 변경하지 않음 |

메뉴 12종과 상세 5종을 확인했다. 717px 기본 창과 390px/1280px 반응형 화면, light/dark를
사용했다. 390px/1280px 메뉴 검사에서 페이지의 수평 넘침은 없었다. 표·타임라인의 내부
스크롤과 실제 글자 읽기는 별도로 화면을 확인했다. 단순 scrollWidth 검사만으로 디자인
완료를 판정하지 않았다. 검증용 viewport override는 종료 전에 해제했다.

중편 검토 기록 이름 검사에서는 처음에 전체 펼친 문장에서 기술 fingerprint의 원래 ID까지
검사하여 실패로 집계했다. 검사를 Versions used 목록으로 한정해 재확인했고 18개 모두
통과했다. 원래 ID가 fingerprint 상세에 남는 것은 의도한 보존 동작이다.

## 회귀 및 산출물

- `npm run check`: 엔진 1,733개 통과, lint/typecheck 통과.
- viewer 회귀 54개 통과: 중첩 값/사용자 키 충돌/각주(이미지 참조 포함)/잘린 원본/타임라인/연결/검사 카드/버전 참조 검사.
- viewer build, lint, diff 검사와 설치 패키지 검증 통과. 실행 로그는 커밋하지 않는다.
- 원본 중편 138개 파일, 안내서 22개 파일의 hash 비교: 변경 없음.
- 시나리오 사건/손상 ledger는 분리된 합성 테스트 사본에만 추가했다. 실제 승인 기록 변경 없음.
- 최신 검토 사본에도 새 UI를 포함했다. 배포 중 기존 창이 이전 JS를 유지하는 상황은 새로고침 후 재확인했다.
- 이번 변경에 데이터 포맷 이전은 없다. 제목/조각/링크 정보는 additive 읽기 필드다. 되돌려도 ledger와 원고는 변하지 않는다.

로컬 증거는 `.local-output/ui-audit-20261010/`의 screenshot, browser text,
`receipt-audit.json`, `original-integrity.json`, `check.log`, `viewer-tests.log`, `package-final.log`다.
실제 작품과 생성 결과물은 커밋 대상에 넣지 않았다.

남은 검증: 실제 초보 사용자의 작업 성공률, 별도 브라우저/스크린리더, 대규모 화면에서의
UX 검증. 전용 EPUB 리더 검사는 이번 표시 수정 범위에서 다시 수행하지 않았다.
