# 이미지 생성은 호스트, Folio는 공통 자산 관리

## 사용자 지정 방향

이미지는 MCP를 사용하는 호스트가 생성한다. 호스트는 자체 이미지 도구 또는
원하는 제공자의 API를 사용할 수 있다. Folio에는 제공자별 생성 연동을 넣지 않는다.
Folio는 범용 MCP로서 작품과 자산의 데이터·상태·검토·승인 기록을 관리한다.

## 공통 인터페이스의 책임

- Folio 고유 자산 ID로 설명서와 원고·펼침면·엔티티의 연결을 유지한다.
- 호스트가 결과를 보관 가능한 파일 또는 리소스 참조로 인계한다.
  제공자 이미지 ID는 선택적인 출처 정보로 보존하고 필수 식별자로 쓰지 않는다.
- 같은 논리 자산의 버전과 내용 hash를 구분한다. 생성 결과가 교체됐는데
  이전 검사·승인을 새 버전의 결과로 취급하지 않는다.
- 생성·이미지 내용 검토는 호스트가 수행한다. Folio는 전달받은 결과와
  확인 가능한 데이터 상태를 관리한다. 접근할 수 없는 참조의 내용을 검증했다고 주장하지 않는다.
- 동일 호스트의 자기검토, 참고 의견 비자동수정, 승인 불가 및 추가만 되는 기록장
  규칙을 유지한다. 이미지 관리도 원고와 같은 책임 구분을 따른다.
- 호스트에 이미지 생성 기능이 없으면 설명서와 대기 상태를 관리한다.
  MCP 연결만으로 모든 호스트가 그림을 생성할 수 있다고 안내하지 않는다.

## 제외

Folio 내부의 제공자별 SDK·API 키·모델 선택·생성 요청·비용 관리·작업 폴링,
외부 리소스 자동 다운로드, 지면 배치·인쇄용 파일 제작은 이 인터페이스에 포함하지 않는다.

## 구현과 검증

공통 자산 도구 `folio_assets`를 구현했다. [구현 계획과 수용 결과](2026-10-04-assets-implementation.md)에
등록·인계·버전 교체·검토·작가 결정, 원고 범위와 재검사 연결의 코드·테스트 근거를 기록한다.
별도 image 팩 파이프라인은 필요하지 않으며 생성은 계속 호스트 책임이다.

합성 파일과 호스트로 상태·잠금·실제 stdio MCP 흐름을 검증한다.
실제 생성 도구의 품질이나 시각 검토 정확도를 검증했다고 주장하지 않는다.
실제 생성 그림은 커밋하지 않는다.
