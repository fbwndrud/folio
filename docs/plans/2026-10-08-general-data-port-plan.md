# Folio 범용 데이터 기반 이식 계획 초안

작성일: 2026-10-08. [범용 AI 작업 설계](2026-10-08-general-ai-work-data-design.md)의 구현 순서다.
이번 변경은 설계·용어·출시 방향의 정리다. 아래 신규 실행 기능은 아직 구현하지 않았다.
기존 착수 계획서 아티팩트와 잠금 규칙을 보존하며 범용 기능은 별도 계약으로 추가한다.
코드 조사 뒤 우선순위는 [검증 후 구현 계획](2026-10-08-architecture-audit/implementation-plan.md)으로 갱신했다.
현재 결함 보완을 범용 기반보다 먼저 수행하며 아래 표는 초기 이식 후보로 보존한다.

## 1 이식 방식

Vibelore 작업 트리는 읽기 전용으로 유지한다. 가져올 계약별로 원본 파일과 내용을 고정한
이식 기록을 남기고, 코드를 실제로 재사용할 때 원본 저작권·라이선스·NOTICE를 함께 확인한다.
대상 코드와 테스트는 Folio에 맞춰 작성한다. Vibelore 패키지 전체를 의존성으로 넣거나,
원본 프로젝트를 수정하며 Folio용 분기를 만드는 방식은 쓰지 않는다.

| 이식 대상 | Vibelore 출처 | Folio에 남길 의미 | 분리할 의존성 |
|---|---|---|---|
| 정의·판본 검증 | `engine/src/lore/registry.js` | 안정적 식별·정의 판본·지원 기능 검증 | 세계 시간·인물 상태·세계별 등록부 |
| 입력 봉인 | `src/core/input-objects.js` | 내용 사본과 hash를 먼저 쓰고 이후 발행 | PNG/JPEG 전용 경로·world lock |
| 제작 원천 계약 | `src/core/production-source.js` | 다양한 원천을 같은 입력 묶음으로 구성 | novel/script 분류·장면 DTO |
| 자산 이력 | `engine/src/lore/assets.js`, `src/store/asset-catalog-store.js` | ID/판본/bytes·파생 관계·채택 HEAD | universe/entity/state 필수 연결 |
| 발행·복구 | 같은 카탈로그, `src/core/scene-script.js` | 충돌 검출·재시도·중단 복구 | 대본 파일 반영·웹툰 제작 |

이식은 설계 계약 재사용을 우선한다. 기존 Folio의 hash·기록장·파일 안전 처리가 같은 책임을
이미 맡고 있다면 그것을 재사용한다. Vibelore의 직렬화 hash를 Folio 기록장 hash로 바로
교체하거나 기존 판본을 새 계산법으로 재해석하지 않는다. 형식·계산법의 버전을 명시한다.

## 2 첫 구현의 범위

한 로컬 작업 공간에서 텍스트·구조화 JSON·현재 지원 이미지와 두 종류의 작업을 다룬다.
첫 작업은 원본 자료에서 안내문을 만드는 호스트 작업이고, 두 번째는 같은 자료를 참조해
호스트가 만든 이미지를 연결하는 작업이다. 번역·요약은 표현 프로필과 별도 파이프라인의 변형이다.
이는 실행 계약 검증용 합성 사례이며 실제 제품 설명이나 생성 이미지를 커밋하지 않는다.

첫 버전에서 임의 오디오·영상 제작, 모든 파일 미리보기, 작업 공간 간 공동 보관함,
분산 실행·복잡한 DAG·서버 동기화는 구현하지 않는다. 지원하지 않는 기능은 정상 완료로 처리하지 않는다.
기존 집필 팩과 원고 잠금을 유지하며 일반 결과 자원을 원고 영수증으로 위장하지 않는다.

## 3 책임을 나눌 Module

| Module | 외부 Interface 초안 | 책임 |
|---|---|---|
| ResourceHistory | propose/readRevision | 자원 정체성·불변 판본·보관된 내용 검증 |
| DefinitionRegistry | inspect/readRevision | 정의 후보·판본·필요 기능 검증 |
| InputSnapshots | prepare/read/verify | 판본 선택·필수 내용 봉인·입력 hash |
| PipelineRuns | start/resume/submit | 작업·요청 결속·재시도·호스트 응답 검증 |
| Publications | inspect/decide/recover | 결정·검사·충돌 확인·발행 및 복구 |
| ResourceProjection | rebuild/query | 원본·결과·파생 관계와 변경 영향 조회 |

Interface 이름과 파일 배치는 구현 착수 때 기존 공개 계약과 대조해 확정한다.
모듈별 책임은 하나이며 구현 파일은 300줄 이하로 나눈다.
`core/`에서 모델·네트워크·제공자 SDK를 호출하지 않는다.
새 범용 Adapter 구조는 실제 텍스트 작업과 이미지 반입 작업의 차이를 확인한 뒤 만든다.

## 4 단계와 수용 조건

| 단계 | 구현 결과 | 필요한 검증 |
|---|---|---|
| 1 원본·판본 | 자원 등록·핵심 원본 선택·정의 판본·파일/JSON 보관 상태 | ID와 hash 분리, 타입 검증, 불변 내용, 경로 공격, 손수정·고아 후보 차단 |
| 2 고정 입력 | 원본·프로필·검사 기준의 봉인 입력과 참조 상태 | 원본 변경·이동 후 과거 입력 검증, bytes 누락, 입력 예산 초과, 미지원 기능 |
| 3 결과·실행 | 두 작업 형태, request 응답 결속, 파생 관계·검토·선택·복구 | 잘못된 요청·hash, 중복/지연 응답, 중단 재시도, 경쟁 채택, 원본 비변경 |
| 4 조회·비교 | SQL 조회 재구성, 원본별 결과·입력 판본·변경 영향 비교 | 색인 삭제 후 같은 조회, 실패한 재구성의 기존 조회 유지, 최신/과거 구분 |

각 단계는 공개 MCP 또는 실제 호출자 Interface에서 동작을 검증한다.
내부 객체 모양만 같은지 확인하는 테스트를 늘리는 것으로 수용하지 않는다.
기존 집필·추적·자산 잠금에 영향을 주는 단계는 기존 검증을 함께 수행한다.
검색·위키·벡터·범용 화면은 이 기반 이후의 별도 구현이며 관련 API를 먼저 약속하지 않는다.

## 5 합성 시나리오

합성 제품 `sample-device`의 사양 판본 A와 표현 프로필을 등록한다.
안내문 파이프라인과 이미지 연결 파이프라인이 같은 A를 참조하도록 준비하고,
테스트 호스트의 고정 응답을 제출해 각 결과를 검토·채택한다.

원본을 판본 B로 변경한 뒤 A의 실행과 결과가 그대로 검증되는지 확인한다.
새 결과는 B를 지정해야 하며, 이미 생성한 결과에 최신 B를 소급해서 연결하지 않는다.
영어 결과를 추가해도 제품 원본과 한국어 결과는 유지되어야 한다.
원본 변경은 참조한 결과에 재검토 사유를 표시하되 결과 파일을 자동 수정하지 않는다.

중단된 발행을 복구하고 같은 요청을 재제출해도 결과·결정이 중복되지 않는지 확인한다.
두 실행이 같은 활성 판본을 교체하려 하면 기대한 HEAD가 다른 쪽은 충돌로 멈춘다.
파일이 있고 검토 응답이 왔다는 사실만으로 후보를 채택 상태로 만들지 않는다.

생성 품질은 별도 시험이다. 합성 응답으로 실행 계약을 확인한 뒤 실제 호스트에서
원본 사양 유지, 언어·스타일 적용, 이미지 참조 반영, 수정 시간을 평가한다.
실제 사용자 자료·생성 결과는 저장소에 커밋하지 않는다.

## 6 기존 기능과 이행

새 기록은 별도 버전의 자원·입력·발행 계약으로 추가한다.
기존 작품은 현재대로 열 수 있어야 하고 신규 메타데이터가 없다고 강제 이행하지 않는다.
기존 원고나 이미지의 일반 자원 연결이 필요하면 명시적 반입 manifest를 남긴다.
과거 승인을 새 범용 작업 승인처럼 재해석하지 않는다.

집필용 `main`은 유지한다. 일반 변형 결과물을 만들기 위해 기존 설정의 지원 목록을 풀거나
leaf/branch의 draft/events 조건을 제거하지 않는다.
원본 hash·영수증·hard·추가만 되는 기록장·자기검토·soft 비자동수정을
비활성화하는 설정은 어느 파이프라인에도 만들지 않는다.

백업은 채택된 판본·입력·결과 bytes·결정 기록을 포함한다.
누락된 bytes를 외부 ID로 대체해 복구 완료라고 표시하지 않는다.
이행 실패 시 기존 작품을 그대로 사용하고, 발행 중단은 승인 상태와 사용자의 새 편집을
확인해 복구한다. 중단 후 새 편집을 이전 승인 bytes로 덮어쓰지 않는다.

## 7 이번 설계 반영 확인

| 사용자 방향 | 반영 위치 |

| 모든 변형의 입력·결과를 확인 | 범용 설계 5·8절, 단계 2·4 |
| Vibelore에서 필요한 것 이식 | 소스별 이식 표와 단계별 검증 |

이 표는 설계 반영 점검이다. 각 구현 단계가 끝나면 실행 증거를 별도로 기록한다.
