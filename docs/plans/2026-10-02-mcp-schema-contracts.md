# Folio MCP 스키마 보완

사용자 지시: Vibelore 공개 스키마와 비교한 검토 결과를 바탕으로 Folio 자체 스키마를 보완한다.
기준 커밋: 588d357. Vibelore API 호환 도구나 새 집필 기능을 추가하는 작업은 아니다.

## 변경 범위

- 14개 도구의 모든 명명된 인자에 한국어 설명을 붙이고 실제 기본값을 명시한다. 기본값은 메타데이터이며 입력을 자동 변경하지 않는다.
- 작업별 필수·허용 인자 규칙을 스키마와 처리 함수가 공유한다. 자료 추가는 text/path 중 정확히 하나, 수정 요청은 feedback, 실행 버림은 reason이 필요하다.
- 실행의 mode/node/variant 조건과 내보내기의 output 조건을 입력 스키마로 나타낸다. 원고·파일·현재 질문에 의존하는 검증과 잠금은 코어가 계속 담당한다.
- 수동 검증기에 선언된 조건부 JSON Schema 키워드를 지원한다. 외부 표준 검증기와 동일한 입력 판정을 확인한다.
- 실제 효과에 맞는 annotations를 공개한다. 혼합 작업·캐시·뷰어는 단순 조회로 표시하지 않는다.
- 도구별 출력 스키마와 structuredContent를 공개한다. 성공은 `{ result }`, 오류는 `{ error }`이며 null 그림 대기도 result에 담을 수 있다. 기존 text 응답 형태는 유지한다.
- 잘못된 입력은 처리 함수보다 먼저 TOOL_INPUT_INVALID로 거부하므로 기존 조건별 인자 오류를 기대한 서버 검사를 갱신한다.

## 검증

조건별 정상·비정상 입력과 외부 JSON Schema 검증기 비교, 실제 MCP 카탈로그·구조화 성공/오류·null·모델 질문, 모든 도구의 실제 결과 계약을 검사한다.
Node 24에서 전체 린트·타입 검사·테스트를 실행한다. 기존 잠금 검사는 그대로 유지한다.
외부 의존성을 추가하지 않으며 실제 작품은 읽거나 수정하지 않는다. 원래 checkout과 이식 원본은 그대로 둔다.

## 완료 결과

2026-10-02 Node 24에서 린트·타입 검사와 전체 1335/1335 테스트가 통과했다(기존 1331개에서 4개 증가).
모든 도구의 조건별 입력을 MCP SDK의 표준 JSON Schema 검증기와 비교했고, 중첩 인자 설명·메타데이터 공개를 확인했다.
유니코드 코드 포인트 기준 문자열 길이와 boolean 부분 스키마도 검증기에 반영했다.
실제 stdio MCP로 14개 도구의 정상 결과와 오류 계약을 모두 검증했으며, 노드·그림의 모델 요청→승인→커밋, 이름 바꾸기, 자료 추가·조회·연결, 가져오기·내보내기와 null 그림 대기를 포함한다.
기존 텍스트 응답을 읽는 호스트 검사도 그대로 통과했다. 코어의 잠금·승인·기록장 구현과 런타임 의존성은 변경하지 않았다.
인자 형식이 잘못된 호출은 이제 더 일찍 TOOL_INPUT_INVALID로 거부된다. 원격 저장소가 없어 push·공개 전환·Glama 등록은 수행하지 않았다.
