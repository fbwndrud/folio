# 쉬운 설명 내재화와 그림책·동화책

## 사용자 요청과 범위

ELI5의 큰 그림·짧은 설명 방식을 Folio에 내재화한다. 그림책과 동화책을
서로 다른 집필 형식으로 고려하고, 사람용 실습책을 공개 독자가 읽는 기준으로 고친다.
실제 작품·삽화·책의 생성 결과는 추적하지 않는다.

현재 엔진은 로컬 stdio MCP이고 root는 절대 경로다. 사람용 본문에서
개발자의 경로를 제거하는 것과 설치 없는 브라우저 서비스를 만드는 것은 별개다.
이번 작업은 호스트 스킬·집필 프리셋·문서·합성 실행 예제에 한정한다.
사용자가 브라우저 서비스까지 지정하면 저장·권한·모델 연결의 별도 설계가 필요하다.

## 구현

- 호스트 스킬에 쉬운 설명 원칙을 넣고, 그림 설명과 상세 실습은 별도 참조로 둔다.
  설명을 쉽게 하는 것과 실제 독자가 어린이인 것을 구분한다.
  원고의 대상·문체·분량은 작가와 정하고 기술 설명은 연결 안내로 분리한다.
- novel 팩의 `picturebook`은 book → spread, `fairytale`은 chapter → scene.
  기존 파이프라인과 잠금을 재사용한다. core는 모델·네트워크를 부르지 않는다.
- 그림책의 펼침면 원고에는 읽을 글과 그림 설명을 구분한다. 그림 설명은
  제작 지시이며 생성·승인된 삽화나 출판용 지면을 의미하지 않는다.
- 어린 독자·읽어주기·글과 그림의 역할에 대한 모델 검토는 experimental advisory.
  참고 의견 자동 수정, hard 우회, 자기검토를 독립 검토로 표기하지 않는다.
- 공개 사람용 본문은 제목·독자·목표·계획·수정·승인·완성 확인 중심이다.
  개인 경로, 터미널 명령, 특정 앱의 버튼은 연결 안내로 분리한다.
  존재하지 않는 작품 목록·클라우드 저장·뷰어·내보내기를 있다고 쓰지 않는다.

## 검증

- 합성 그림책·동화책 입력으로 실제 stdio MCP 완료·원고·기록장·최종 상태 확인.
- 그림책에 참고 지적을 남긴 실행에서 본문 비자동수정과 자기검토 표기 확인.
- 두 프리셋의 잠긴 단계와 hard 차단, 잘못된 프리셋의 기존 안내 확인.
- lint, typecheck, 전체 테스트와 예제 실행.
- 사람용 읽기본의 개인 경로·외부 스킬 경로·로컬 서버 URL 제외 확인.
- 실제 초보 사용자 학습 효과, 삽화 품질, 시장 수요는 검증했다고 주장하지 않는다.
