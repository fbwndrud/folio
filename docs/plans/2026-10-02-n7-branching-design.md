# N7 분기·게임북 설계 초안

상태: **구현·독립 검토·J4 로컬 통합 완료**. 기반 main `ba3dd5c`. 2026-10-02 사용자의 “이후 다음 작업들도 끝까지 진행해”를 N7 추천안과 구현·독립 검토·J4 로컬 통합 승인으로 기록한다. 상세 판정은 2026-10-02-n7-branching-rulings.md에 남긴다.

## 근거와 목표

로드맵 L3 N7: `order: branching`, 첫 팩 `gamebook`, 경로별 사건 검사, 막다른 분기와 도달 불가 장면. N4·N6은 main에 병합됐다. 정본 아티팩트는 읽기 도구에서 접근할 수 없어 로컬 로드맵·N4/N6 계획·판정과 현재 코드로 설계를 제한한다. 이 초안을 새 설계 정본으로 승인받아 구현 계획의 근거로 삼는다.

선택지가 갈라졌다가 다시 합쳐지는 작품에서 한 경로의 죽음이나 물건 파괴가 다른 경로로 새지 않아야 한다. 파일 배치는 편집 순서일 뿐 독자의 이동 순서가 아니다. 경로 계산은 코어의 순수 모듈, 의미 판정은 팩의 순수 검사기로 둔다. hash·영수증·hard·기록장·자기검토·soft 잠금은 그대로다.

## 비교한 접근

| 안 | 방법 | 장점 | 비용과 판단 |
|---|---|---|---|
| A | 역방향으로 도달하는 모든 사건을 합친다 | 작은 계산량 | 양립할 수 없는 길의 사건을 섞으므로 버린다 |
| B | 진입점에서 대상까지의 단순 경로를 각각 계산한다 | 실제 경로를 지적으로 보여 주며 경로별 상태를 분리한다 | 경로 폭주 상한·순환 미완료 표기가 필요하다. **추천** |
| C | 상태 전이의 고정점으로 경로별 사실을 압축한다 | 큰 그래프와 반복을 더 잘 다룰 수 있다 | 상태 종류마다 별도 결합 규칙이 필요해 코어가 팩의 의미를 알게 된다. N7에는 보류 |

B는 반복 방문을 완전히 해석하지 않는다. 순환을 발견하면 그 사실과 계산의 한계를 남긴다. 무한한 경로를 일부만 계산하고 전체 검사 완료로 표시하지 않는다.

## 작품 데이터와 연결

노드 앞머리의 기존 `links: [{ to, kind, label }]`를 정본으로 유지한다. `kind: choice`만 독자의 이동이다. `see-also` 등은 현재 N4 연결 조회의 뜻을 유지하고 경로에 넣지 않는다.

대상 정점은 `role: body`, 잎 노드, 유효 위치의 `unorderedBy: branching`인 노드다. front/back 가지 아래의 자손도 제외한다. 장·파트 같은 가지는 계획이며 이동 정점이 아니다. 장 사이 이동은 잎 id를 직접 가리킨다. front/back은 진입점이나 이동 정점이 아니다. `none`과 `branching`이 겹칠 때 N4의 branching 우선 규칙을 유지한다.

잎 노드에 다음 메타데이터를 더하는 안을 추천한다.

```yaml
branching:
  entry: true
  ending: false
links:
  - { to: left-path, kind: choice, label: 왼쪽 길 }
  - { to: right-path, kind: choice, label: 오른쪽 길 }
```

- `branching.entry: true`: 독자가 시작할 수 있는 장면. 여러 진입점을 허용한다.
- `branching.ending: true`: 의도한 끝. 종료점에서 나가는 choice는 데이터 모순으로 지적하고 탐색을 종료한다.
- 빠진 플래그는 false. 정해진 필드 밖 키·불리언이 아닌 값·잎이 아닌 노드의 표시는 그래프 진단이다. 잘못된 값을 true로 추정하지 않는다.
- 진입점이 없으면 명시적인 `BRANCH_ENTRY_MISSING`을 낸다. 폴더 첫 장면이나 들어오는 링크가 없는 노드를 시작점으로 추정하지 않는다.
- 없는 대상, 가지 대상, 다른 순서/역할의 대상은 `BRANCH_TARGET_INVALID`. 자기 선택·중복 선택은 별도 진단한다. 유효하지 않은 간선을 탐색하지 않는다.
- 목표를 지정한 연결 순서는 choices의 표시 순서일 뿐이다. 계산 결과의 경로 id는 노드 id와 이동 id로 안정적으로 만든다. 폴더 순서만 바꿔도 참고 버전이 변하지 않게 한다.

N7은 선택지를 자동으로 쓰거나 앞머리를 고치지 않는다. 생성 요청은 기존 코어 단계가 처리하는 원고·계획·사건·자식 목록만 만든다. 연결과 진입·끝 표시는 작가가 앞머리에 적는다. 새 링크 쓰기 도구·조건부 선택·확률·변수 시스템은 이 범위 밖이다.

## 코어 모듈과 계산 한계

외부 인터페이스는 `branchScope({ work, events, receiptRecords, nodeId })` 한 곳에 모은다. 내부 그래프 추출과 탐색은 책임별 파일로 나누되 호출자는 경로 알고리즘을 알아야 하지 않는다. 새 코드 파일은 300줄 이하. `runner.js`는 250줄 이하를 유지하고 새 경로 실행기를 만들지 않는다.

반환 의미:

- `applicable`: 대상이 분기 잎이며 `features.branching`이 켜져 있는가.
- `graph`: 유효 정점·간선·진입점·끝·도달 가능 집합과 그래프 진단.
- `paths`: 진입점에서 대상 직전까지의 **경로별** 노드 id와 사건 목록. 대상 자체의 기존 사건은 넣지 않는다. 대상 초안 사건은 검사기가 뒤에 붙인다.
- `complete`: 관련 탐색에서 순환·상한·자료 불완전이 없이 전체 경로를 계산했는가.
- `problems`: 경로 절단·순환·미검사 사건 등 확정할 수 없는 이유. `rev`: 그래프와 관련 사건을 묶는 안정된 hash.

반복 없는 경로는 모든 진입점에서 대상까지 각각 보존한다. 진입점이 대상이면 앞 사건 없는 경로가 하나다. 대상에 도달할 수 없는 진입점/분기는 대상 사건 범위에서 제외한다. 서로 다른 길이 합쳐져도 사건 목록을 하나로 합치지 않는다.

우선 상한은 정점 5,000, 이동 20,000, 대상 경로 256, 경로 길이 512, 탐색 상태 100,000으로 제안한다. 상한은 결과로 공개하고 고정된 순서로 탐색한다. 재귀 호출 대신 깊이 우선 탐색의 프레임 스택을 사용하고 현재 경로를 push/pop한다. 모든 대기 상태마다 512개 id 복사본을 쌓지 않는다. 상한을 넘으면 `complete: false`, 절단 이유와 확인한 경로만 준다. 전체 도달 가능성은 선형 탐색으로 별도 계산하므로 경로 256개 절단이 곧 도달 불가로 오인되지 않는다.

순환은 SCC 또는 동등한 선형 계산으로 찾는다. 대상의 앞쪽에 있는 순환은 단순 경로를 계산해 참고 지적을 낼 수 있으나 반복에 따른 상태를 다 본 것은 아니므로 미완료다. 종료점에 도달할 수 없는 순환과 종료점으로 빠져나갈 수 있는 순환을 구분한다. 관련 없는 먼 순환은 대상 경로의 완료 여부를 떨어뜨리지 않는다.

## 사건·검사 문맥

현재 `eventsBefore`는 linear에만 적용된다. 이를 바꾸지 않는다. `scope.ordered`는 branching에서 false이고 `priorEvents`는 빈 목록이다. 기존 `linkedEvents`는 none의 연결 사건이며 분기 사건을 합쳐 싣지 않는다. branching 케이스는 별도 `branching` 문맥을 제공하는 인터페이스로 연결한다.

각 경로의 사건은 경로 노드 차례, 같은 노드의 seq 차례다. 기본 자료는 현재 코어가 제공하는 main의 활성 사건이다. receiptRecords는 호출자가 한 번 읽어 넘기고, 사건의 귀속 commit/영수증과 노드 현재 본문 hash를 검증하는 데 쓴다. 순수 모듈이 기록장을 직접 열지 않는다. N6 판본 사건은 모으지 않는다. 선택 경로의 어떤 노드가 import/draft/planned/손수정 상태이거나 main commit/영수증 결속이 없어 신뢰할 Folio 사건이 없으면 이를 `BRANCH_EVENTS_UNVERIFIED`로 명시하고 그 경로를 완료로 표시하지 않는다. 이 경로의 사실 충돌은 확정 지적으로 내지 않고 미검증 사유만 남긴다. 다른 완전 경로의 사실 검사는 계속 수행한다. 가져오기만 했다는 사실을 검사된 사건이 있다는 뜻으로 바꾸지 않는다.

일반 모델 요청에는 `branching.paths`, `complete`, `problems`를 경로별로 싣는다. 엔티티 범위는 현재 대상의 등장·추출·스캔 범위를 유지한다. 대상이 보지 않는 다른 길의 사건을 payload에 더하지 않는다. 메모리와 payload는 탐색 상한과 함께 전체 반환 사건 항목 20,000개, 직렬화된 경로 문맥 2MiB로 제한하는 안을 추천한다. 한 경로라도 사건/바이트 한도로 잘리면 BRANCH_ANALYSIS_INCOMPLETE를 남기며 완료로 보지 않는다. 구현 계획에는 이 수치를 테스트로 고정한다.

판본 실행은 N6의 `variantScope`·`variantPayload`를 그대로 쓴다. 게임북 구조와 사실 검사는 main만 수행한다. `requiresOrder: branching`의 해당 여부는 분기 문맥의 `applicable`도 확인하므로 판본 실행을 main 경로 검사로 오인하지 않는다.

`core.promise-order`는 계속 `requiresOrder: linear`이며 branching에서는 `not_applicable`로 기록한다. 분기 약속을 그 잠금에 넣는 의미 변경은 하지 않는다. 게임북의 경로 사실 검사가 심기/해소를 따로 다룰지는 후속 범위다.

## 게임북 팩

`packs/gamebook`은 첫 팩이다. 프리셋은 `gamebook`: chapter(계획 가지) → scene(잎), `order: branching`. 최초 세트는 `gamebook.basic`. 작가가 고르는 세트이며 새 검사 모두 `experimental: true`, 기본 `advisory`. block으로 올리려면 기존 검사 설정·이유 있는 승인 규칙을 따른다. 새 hard 검사나 hard 해제가 없다.

잎 단계는 기존 plan → draft → extract → facts → critic → revise → approve → commit 구조를 사용한다. 가지는 기존 plan → fit → revise → approve → children → review → commit 구조다. 단계 정의·한국어 프롬프트는 팩에 두고 코어에서 novel 팩을 import하지 않는다. soft 지적은 revise를 자동으로 돌리는 이유가 아니다.

| 검사 | 대상과 결과 |
|---|---|
| `gamebook.dead-ends` | 도달 가능한 비종료 장면에 유효 choice가 없거나 종료점으로 가는 길이 없다. 종료점과 미작성 분기를 구분한다 |
| `gamebook.unreachable` | 어떤 명시 진입점에서도 도달하지 못하는 장면. 그래프 자체가 진입점 없이 불완전하면 그 원인을 먼저 내며 전 장면을 단정하지 않는다 |
| `gamebook.paths` | 잘못된 대상·표시, 순환, 경로/사건 한도, 미검사 자료. 부분 계산을 전체 통과로 오인하지 않도록 이유를 기록한다 |
| `gamebook.path-facts` | 각 경로에서 최신 state/data.vital을 따로 접어 죽은 인물이 대상에 등장하는지, 최신 state/data.exists가 destroyed인 물건이 등장하는지 확인한다. 인용 있는 되살림·복구는 기존 소설 검사와 같은 근거 원칙을 따른다 |
| `gamebook.critic` | 선택 동기·선택지 구분·장면 몰입의 모델 검토. 같은 호스트 자기검토 표기 |

`path-facts`는 임의의 state 필드를 생사나 파괴로 추정하지 않는다. 모르는 값은 구체 경로와 엔티티를 포함한 참고 지적이다. 한 경로의 정상 상태가 다른 경로의 충돌을 지우지 않는다. 지적에는 `pathId`, 진입점, 앞 노드 id, 엔티티 id를 넣어 작가가 재현할 수 있게 한다. 파괴 값은 현재 novel.destroyed-object와 같은 exists: destroyed/restored다. 생사 값은 vital: dead/alive다.

가지의 review에서 자식 전체 그래프 요약을 볼 수 있게 하되 경로 사실 검사는 잎에서 수행한다. 가지 초안에 전체 장면의 사건을 섞어 추출하지 않는다. 그래프 진단 반복 출력은 대상과 코드로 안정적으로 중복을 제거하되 서로 다른 경로의 충돌은 지우지 않는다.

## 기능 토글·영수증·변경 전파

`FEATURES` 끝에 `branching: true`, `FEATURE_PARENTS.branching: links`, `RUN_FEATURES` 끝에 branching을 추가한다. branching은 경로 계산/문맥을 켜고 끈다. 영수증 features에는 branching을 선택적 불리언으로 추가하고 과거 occurrenceScope만 있는 영수증을 계속 받는다. 새 featureReason은 경로 검사가 적용되는 노드의 branching 전환도 재검사 이유로 낸다. 분기와 무관한 옛 linear/none 영수증은 새 필드가 없다는 이유만으로 stale로 만들지 않는다. RUN_FEATURES digest 필드 추가로 열린 실행이 한 번 재검사될 수 있는 업그레이드 효과는 별도로 기록한다. 검사 세트는 별도 선택이다. 꺼진 기능을 통과라고 적지 않고 해당 없음 또는 이유 있는 건너뜀으로 기록한다. 잠금은 토글과 무관하다.

`yaml-schema`와 JS 팩 정규화의 `requiresOrder`에 branching만 추가한다. linear·none의 뜻은 보존한다. 체크 문맥·payload·영수증 refs에서 대상의 경로별 자료를 공통 인터페이스로 계산한다.

부분 계산은 gamebook.paths 지적 BRANCH_ANALYSIS_INCOMPLETE에 구체 이유로 남긴다. 기존 영수증의 passed는 차단 지적 없음이며 전체 경로 검증 보증으로 표시하지 않는다. 수용 테스트는 incomplete 지적 보존을 확인한다.

새 ref `{ kind: 'branching', id: nodeId, rev }`는 그래프, 관련 경로 사건과 자료 검증 상태를 결속한다. `currentRev`와 범위 생성은 같은 순수 계산을 쓰고 receiptRecords를 전달한다. gatherScope/entityRevAt/findStale 호출부에는 이 입력을 선택적으로 추가하되 분기 기능이 적용되지 않는 기존 계산은 같은 값과 모양을 유지한다. 진입·끝·choice·관련 사건을 바꾸면 커밋 직전 재검사를 하며 이후 stale로 표시한다. 폴더 이동·무관한 엔티티 사건은 경로 의미가 같을 때 불필요하게 stale로 만들지 않는다. topology를 전체 작품 단위로 hash하면 무관한 choice 편집까지 stale일 수 있으므로 구현 계획에서 관련 앞쪽 그래프와 전체 구조 검사 refs를 분리한다.

N4의 `orderReason`/실행 sync는 ordered 불리언만 비교한다. N7에서는 none ↔ branching 전환과 부모의 유효 순서 전환도 검사 해당 여부를 바꾸므로 `unorderedBy`를 포함한 유효 방식 비교로 넓힌다. 옛 linear/none 영수증에 새 필드를 요구해 검증 실패시키지 않는다. 분기 검사를 선택한 옛 branching 영수증에 경로 ref가 없으면 재검사를 권한다. N6 main 기본 필터, 원본 결속, 판본 영수증 검증은 그대로다.

영수증이 이미 기록된 committing 복구는 현행 코어의 같은 영수증 복구 규칙을 따른다. 새 경로 기능도 이미 기록된 영수증을 손으로 바꿔 새 검사처럼 취급하지 않는다. 이 예외와 신규 검사 전 변경 감지 모두 수용 테스트로 확인한다.

## 구현 계획의 분할안

1. 합성 `gamebook-n7` fixture와 순수 그래프/도달성/경로 탐색. 기존 gamebook fixture 무변경.
2. 사건을 경로별로 모으는 branchScope와 완료/절단/진단 계약.
3. scope·payload·refs·stale·sync와 N6 판본 분리. 가장 강한 잠금 공격 검토.
4. 게임북 첫 팩·프리셋·단계·프롬프트·검사기. 팩/기능 목록 끝 추가와 목록 테스트.
5. MCP 수용, 기존 linear/none 회귀, 단계·세트·토글, 문서·호스트 안내.
6. 독립 전체 검토 후 한 번의 최종 수정과 범위 재검토. 승인 후 main 통합.

전체 코드 계획, 합성 시험, 세 태스크 구현·독립 검토와 최종 수정·재검토를 완료했다. 결과는 2026-10-02-j4-integration-results.md에 기록한다.

## 완료 기준과 공격 시험

- 동일 엔티티가 왼쪽 길에서 죽고 오른쪽 길에서 살아 있는 합류: 왼쪽만 지적한다. 관련 없는 가지에서의 죽음은 전달되지 않는다.
- 진입점 여럿, choice 표시 순서 변경, 장 사이 선택, 종료점, 도달 불가 장면, 자기 루프·다중 순환·무종료 SCC, 깨진 대상, front/back·none 대상.
- 폭주하는 DAG·긴 경로·사건 과다에서 시간/메모리를 제한하고 `complete: false`를 남긴다. 없는 사건을 정상 사실로 만들지 않는다.
- 폴더 재배치의 rev 안정성, 관련 choice/진입점/종료점/사건 변경의 실행 중 재검사와 커밋 뒤 stale, none ↔ branching 전환.
- 기능·세트·facts/critic 토글로 hard/hash/영수증 잠금을 우회하지 못한다. 잠금 단계 설정은 거부된다.
- import 기록만 있는 경로 자료는 검사되지 않은 상태로 보인다. main 사건/영수증과 N6 판본이 섞이지 않는다.
- 기존 linear/none, N6 원본 변경 차단·committing 복구, M7b imported/recommit 수용을 함께 통과한다. 새 합성 데이터만 사용한다.

## 자기 검토와 남은 결정

- A의 경로 사건 합치기는 배제했다. B의 상한·순환·불완전 사건을 결과에 드러내는 것으로 오판을 줄인다.
- 명시 진입점·종료점, 단순 경로 모델, 제안 상한, 기본 branching 토글, 첫 세트/팩 이름은 **승인된 추천안**이다.
- destroyed-object 사건 필드는 코드로 확인했다(exists: destroyed/restored). 경로 사건·바이트 상한은 위 제안 수치다. topology ref의 정렬/부분 집합은 위 의미 계약을 만족하는 전체 코드와 테스트로 구현 계획에서 고정한다.
- M4 잔여 minor(동명 후보 누락, 조용한 dedupe, baseHash 미사용, 파일 트랜잭션 경로 중복)는 N7 분기 계산의 직접 요건이 아니다. 별도 정리 범위를 먼저 확정하며 N7에 무조건 끼워 넣지 않는다. isPlainObject 중복은 C0에서 정리된 상태를 기준으로 한다.
- 설계 초안 자체에는 실행 가능한 경로 구현이나 테스트 결과가 없다. 실제 작품·Windows·원격 CI는 검증하지 않았다.
