# 공개 준비: digest, 문서, 합성 예제, CI

## 범위

사용자 요청: digest 문제를 보완하고 문서·합성 예제·CI를 확인한다.
실제 작업물 생성, 등급 제한(S), 숫자 대조 개선, 공개·push·npm 게시는 이번 범위 밖이다.
기존 미추적 로드맵과 읽기 전용 이식 원본은 변경하지 않는다.

## 구현

1. 파일 팩의 모든 JS/CJS/MJS/JSON 파일을 정렬한 상대 경로와 내용 hash로 묶는다.
   보조 파일의 추가·삭제·변경도 digest를 바꾼다. 링크를 따라 읽지 않는다.
2. 결정론 검사별 digest에 함수 소스와 구현 digest를 넣는다.
   열린 실행의 답을 무효화하고, 커밋된 원고는 재검사 필요로 표시한다.
3. JS 함수의 숨은 클로저는 자동 추출할 수 없으므로 `digestInputs`로 명시한다.
   파일 팩 로더는 `checkerInputs`로 팩 밖의 코드·상수에 대한 입력을 받는다.
   선언한 입력은 함수 소스를 대체하지 않는다. 모든 잠금은 그대로 유지한다.
4. 설치·첫 원고·지원 환경·알려진 제한·팩 작성·복구·기여 안내를 쓴다.
5. 합성 단편·교재 입력과 MCP 통신을 사용하는 실행 가능한 예제를 만든다.
   생성된 작품과 `.folio` 상태는 저장소 밖에만 쓴다.
6. CI에서 기존 검사와 합성 예제의 설치/실행 경로를 검증한다.

## 검증

- 수정 전 보조 파일 변경 및 결정론 검사 변경 감지 테스트가 실패하는지 확인.
- 같은 코드의 경로·파일 생성 순서 독립성, 추가·삭제, 링크 차단 확인.
- 열린 요청 `ANSWER_STALE`, 커밋 원고 `recheck`, 옛 영수증 보존 확인.
- Node 24에서 전체 lint/typecheck/test, 합성 예제, 패키지 설치 확인.
- 원격이 제공되면 GitHub Actions 실행 결과도 확인한다.
  원격이 없으면 CI 설정과 로컬 검증만 확인하고 OS 매트릭스를 검증했다고 말하지 않는다.

## 결과 (2026-10-03)

- 회귀 테스트 13개 추가. 수정 전 새 digest 테스트 6개 중 5개가 실패했다.
- macOS, Node 24.19.0에서 lint·typecheck·전체 테스트 728/728 통과(실패·스킵 0).
- 보조 파일 변경 → 열린 답 ANSWER_STALE, 커밋 원고 재검사 표시와 해제,
  기록장 기존 항목 보존을 통합 테스트로 확인했다.
- 두 합성 예제는 실제 MCP stdio 서버로 끝까지 실행하고 본문·기록장·최종 상태를 확인했다.
- tarball 191개 파일을 새 임시 폴더에 개발 의존성 없이 설치한 뒤 같은 예제를 완료했다.
  초기 샌드박스 DNS 차단은 승인된 네트워크 접근으로 다시 검증했다.
  설치 검사에서 발견한 macOS 경로 별칭에 따른 CLI 미실행도 수정·회귀 테스트했다.
- 테스트·계획서·작품 상태는 배포 목록에서 제외했다. manifest/lockfile 의존성 필드는 일치한다.
- 문서의 로컬 링크, git diff 공백, 코드 파일 300줄 제한을 확인했다.
- CI YAML의 6개 조합과 검증 명령을 확인하고 예제/새 설치 검증을 추가했다.
  원격이 없어 GitHub Actions 실제 실행·OS 매트릭스 통과는 확인하지 못했다.
- 잔여 한계: 임의 JS 클로저와 팩 밖 입력은 작성자가 digestInputs/checkerInputs로
  명시해야 한다. 파일 팩 전체 코드 hash는 보수적으로 같은 팩의 검사를 재검사시킬 수 있다.
