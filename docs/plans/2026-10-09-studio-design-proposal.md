# Folio Studio 디자인 개선 시안과 구현 순서

2026-10-09. 상태: 비교 가능한 읽기 전용 시안. 제품 구현 완료 선언이 아니다.

## 판단하려는 질문

중편처럼 원고와 추적 기록이 늘어났을 때, 사용자가 원고를 편하게 읽고,
현재 시점의 상태와 근거를 확인하고, 책으로 나온 결과를 쉽게 판단할 수 있는가?

설치된 `prototype` 스킬과 해당 `UI.md`를 적용했다.
구조가 다른 세 시안을 같은 경로에서 비교한다. 기존 React viewer의 원고 렌더러,
정적 snapshot API, 실제 저장된 중편 데이터와 내보내기 파일을 활용했다.

## 현재 화면에서 확인한 문제

- 전체 Graph는 42개 노드와 158개 연결을 한꺼번에 보여 준다. 화면에 맞추면 라벨이 약 6px이다.
- Entity 화면에는 이번 중편의 tracking observation이 표시되지 않는다.
  편지함의 보관자 변화가 기록되어 있어도 화면에서 바로 확인할 수 없다.
- 현재 EPUB 목차는 18개 장면을 평면으로 보여 준다. 6개 장의 구조가 사라진다.
- 읽기, 근거 확인, 출판 결과 확인 사이에 목적별 화면 구분이 필요하다.

근거: `2026-10-09-novella-and-handbook-results.md`와 실제 viewer/EPUB 산출물.

## 세 가지 시안

| 시안 | 화면 구조 | 사용자에게 주는 이점 |
| --- | --- | --- |
| A · Manuscript workspace | 접는 장별 목차 / 넓은 원고 / 시점별 추적 패널 | 읽던 위치에서 상태와 변화의 근거를 확인한다. |
| B · Evidence desk | 관측 기록 표 / 원문 근거 / 대상·장별 연결 | 명시된 내용과 인물의 믿음을 구분하고 기록을 검토한다. |
| C · Publication preview | 계층형 목차 / 종이 형태 발췌 미리보기 / 실제 export 링크 | 책의 구조와 읽을 결과, 검토용 결과를 비교한다. |

권장: A를 기본 화면으로 삼고 B와 C를 Review / Publish 모드로 제공한다.
세 개 중 하나만 고르는 문제보다 사용 목적에 따라 전환하는 구조가 적합하다.

공통 디자인: 읽기 좋은 원고 폭과 18px 본문, 차분한 크림·녹색, 명확한 선택 표시,
기술 정보는 근거 상세 안으로 이동. 그래프 라벨은 축소하지 않고 13px로 표시한다.
관계 화면은 선택한 대상과 실제 장면 참조만 보여 준다. 참조를 인물 관계로 해석하지 않는다.

## 실제로 연결한 데이터와 한계

- 합성 중편 「파란 우편함의 여름」: 6장, 18장면, 26,721자.
- 기존 공개 MCP 조회 결과의 활성 관측 24개와 호스트 보고 coverage 100/100.
- 원고 근거 클릭은 해당 장면으로 이동하고 실제 인용 문장을 강조한다.
- A는 선택 장면 이후 관측을 제외한다. 단순 fixture의 기준별 마지막 관측을 표시한다.
  제품에서는 관점·충돌·최신성·적용 범위를 함께 처리해야 한다.
- B의 관측 표는 작품 전체 범위다. 근거 패널은 선택 관측의 실제 source section을 표시한다.
- C는 저장 원고의 발췌를 배치한 디자인 시안이다. 자동 페이지 분할이 아니다.
  실제 EPUB은 아직 평면 목차이며 시안에서 새로운 EPUB을 생성하지 않는다.
- 승인·coverage 수치는 합성 실습과 동일 호스트 기록이다. 의미 정확도나 실제 작가 승인을 뜻하지 않는다.
- 시안은 정적 snapshot만 읽는다. 원작품에 쓰기·승인·수정 요청을 보내지 않는다.

## 실제 제품 반영 순서

### 1. 추적 기록의 읽기 계약

대상: `core/view/entity-view.js`, `core/view/snapshot.js`, `server/view/api.js`.
기존 공개 tracking query를 재사용하여 관측·기준·근거·관점·receipt·source hash를
읽기 모델에 추가한다. UI가 ledger를 별도로 해석하지 않게 한다.

완료 조건: live 화면과 snapshot 화면의 같은 revision 조회가 일치한다.
stale / unknown / 누락 범위가 표시되고, 충돌·서로 다른 관점을 하나의 사실로 합치지 않는다.
특정 소설의 캐릭터·보관자 의미는 Core에 강제하지 않는다.

### 2. 원고 중심 화면과 근거 이동

1의 계약 위에 A를 실제 Reader에 적용한다. 기존 ManuscriptBody와 링크 동작을 유지한다.
장별 목차를 접고, 추적 대상 선택과 현재 시점/변화 보기를 제공한다.
모바일에서는 원고를 우선하며 추적 패널을 필요할 때 연다.

완료 조건: 근거 선택 시 올바른 장면·revision·인용 위치로 이동한다.
해시가 다르면 오래된 인용을 현재 원고의 근거처럼 강조하지 않는다.
키보드 포커스와 작은 화면에서도 원고 읽기·장면 이동이 가능하다.

### 3. 근거 검토와 제한된 연결 화면

1과 2 이후 B를 구현한다. 대상·기준·장 필터, 명시/추론/믿음·관점 표시,
선택 근거와 원문 비교, 대상 중심 연결을 제공한다.
연결 유형과 현재 범위를 표시하고 텍스트 목록도 제공한다.

완료 조건: 전체 연결을 기본으로 펼치지 않는다. 필터로 제외된 기록을 안내한다.
자기검토와 작가 승인 상태를 구분한다. UI에서 임의의 semantic 관계를 생성하지 않는다.

### 4. 출판 구조와 export

2 이후 C의 목적별 export 패널을 구현한다.
`core/export/`의 목차 입력에 부모 계층을 추가하여 Web/EPUB에서 실제 장 구조를 보존한다.
부모의 계획 메모는 출판 본문에 섞지 않는다. 레이아웃 미리보기와 실제 파일을 구분한다.

완료 조건: 6장/18장면 계층과 원문 본문 hash가 유지되고 EPUB nav/spine이 유효하다.
실제 EPUB reader에서 목차 이동을 확인한다. PDF는 별도 품질 검증 없이 출판 준비 완료라 표시하지 않는다.

### 5. 초보자 검증과 안내서 갱신

실제 화면 기준으로 원고 → 추적 대상 → 근거 → export의 첫 작업 경로를 설명한다.
원문 버전, 미검토, 오래된 근거를 쉬운 문장으로 안내한다.
독립적인 초보 사용자에게 한 장면의 보관자와 근거 찾기, EPUB 내려받기를 맡겨 평가한다.
이번 동일 호스트 시안 검사를 초보자 사용성 검증으로 대신하지 않는다.

## 테스트·호환·롤백

- 읽기 계약: 미래 정보 제외, 다중 관점·충돌, 오래된 근거, coverage 누락, live/snapshot 일치.
- UI: 근거 이동·강조, 필터 변경, 키보드와 좁은 화면, 정적 export에서 쓰기 요청 없음.
- Export: 부모 계층, 본문 동일성, 유효한 EPUB/XML, 이전 평면 구조 fallback.
- API 필드는 추가 방식으로 도입하고 기존 MCP 계약은 유지한다.
  snapshot에 새 필드가 없으면 기존 원고와 기본 Entity 화면을 계속 보여 준다.
- 롤백은 화면과 읽기 adapter를 되돌리는 것으로 수행한다. ledger나 작품 데이터를 다시 쓰지 않는다.
- hash·영수증·hard 차단·추가만 되는 기록·자기검토 표기·soft 비자동수정은 유지한다.

## 시안 검증 및 산출물

Vite build 성공. 브라우저에서 근거 이동/강조, 미래 정보 제외, 검색 입력 중 단축키,
대상·장 필터, 믿음 기록, 출판 장 선택, 실제 Web/EPUB 링크, 시안 전환을 확인했다.
390/768/1024px의 세 시안과 넓은 화면을 검사했다. 작은 화면의 가로 overflow와
브라우저 page error는 없었고 `/api/` 네트워크 요청은 0개였다.
