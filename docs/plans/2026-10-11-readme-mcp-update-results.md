# README와 MCP 배포 동기화 결과

## 소스 반영

- 영어·한국어 README의 소개를 범용 프로젝트 데이터 관리로 정리했다.
- 두 README와 연결 안내에 stdio JSON 설정, 설치 경로 치환, Node 탐색 실패 대응,
  스킬 별도 연결, 업데이트·재연결·롤백을 추가했다.
- 서버 식별 정보는 server/identity.js가 설치된 package.json에서 읽는다.
  MCP initialize의 instructions와 folio_view 설명에 최신 판본 화면 계약을 반영했다.
- AI용 연결·화면 지침도 같은 계약과 확인 범위를 설명한다.
- root/viewer manifest와 lock의 버전은 0.1.1로 준비했다. 작품 형식·기록장·도구 ID는 유지한다.
- 설치 패키지 검증에서 패키지 이름을 읽어 설치 위치를 찾는다. 변경 후 이름에도 대응한다.

## 실행한 검증

환경: macOS arm64, Node 24.19.0. 아래는 이번 로컬 실행 결과다.

| 검증 | 결과 |
|---|---|
| lint / typecheck | 통과 |
| 백엔드 전체 | 1,762 통과, 0 실패 |
| viewer 전체 | 70 통과, 0 실패 |
| 새 tarball 별도 설치 | 개발 의존성 없이 설치·실행 통과 |
| 설치본 MCP initialize | 설치본 이름·버전과 일치, 0.1.1 확인 |
| 설치본 production 합성 E2E | MCP·HTTP·CLI·Resource·자산·출판 통과 |
| 영어 번역 판본 E2E | 공개 MCP로 두 구간 작성·검토·모의 승인, 원본 영수증 결속 확인 |
| 선택 판본 다운로드 | Web ZIP·EPUB의 실제 영어 본문·언어·CRC 확인 |
| 다운로드의 읽기 전용 성질 | 조회 전후 영수증 기록장 bytes 일치 |
| 설치 문서 링크 | 문서 95개 상대 링크 통과 |
| 패키지 제외 규칙 | 테스트·실제 작품·생성 이미지·구현 계획·모델 가중치 제외 |

Web ZIP 검증을 처음 확장할 때 EPUB mimetype의 무압축 조건을 일반 ZIP에도 적용해
검증 코드가 실패했다. 무압축 조건을 EPUB 검증에만 두고 Web의 deflate/CRC를
실제로 읽도록 고쳤다. 수정 뒤 위 검증이 모두 통과했다.

Vite의 기존 큰 graph chunk 경고와 viewer 테스트의 개발 WebSocket 포트 경고는
남아 있으나 각 명령은 성공했다. 이번에 원격 OS/Node CI 매트릭스의 통과를 확인한
것은 아니다. 모델이나 실제 작가의 승인은 사용하지 않았다.

## 배포 상태

0.1.1 tarball을 로컬에서 만들었고 설치 검증을 마쳤다. 새 이름은 사용자 선택 대기다.
저장소 이름 변경과 새 릴리스 게시는 아직 수행하지 않았다. 최초 v0.1.0 태그와
배포 파일은 덮어쓰지 않았다. 실행 중인 AI 앱의 MCP 연결은 패키지 교체만으로
갱신되지 않으므로 재연결과 초기 응답 확인이 필요하다.
