# 중편과 기존 실습책을 통한 실제 사용 흐름 검증

## 목적과 경계

사용자 요청: 단편보다 긴 작품 한 편과, 예전에 ELI5 방식으로 만든 사람용 실습책의 절차를 실제로 실행해 수정할 지점을 찾는다. 기존 작품과 예전 실습책은 읽기 전용 원본으로 보존한다. 새 합성 원고·호스트 답·스크린샷·내보내기는 `.local-output/novella-guide-20261009/`에만 둔다. 모의 작가 결정은 이 테스트 작품에만 적용한다. 같은 호스트의 작성·검토를 독립 평가나 실제 초보자 실험으로 부르지 않는다.

별도 ELI5 스킬은 설치된 경로에서 찾지 못했다. 실제로 읽은 Folio 스킬과 `skill/folio/references/plain-language.md`에 내재화된 지침을 따른다. 제품 코드를 바꾸기 전에 현재 코드에서 재현한 문제와 설명서의 갭을 구분한다.

## A. 중편 원고

- 새 이야기 `파란 우편함의 여름`: 책→6장→18장면. 반복 fixture를 늘리지 않고 시작·갈등·선택·결말이 이어지는 수만 자의 한국어 본문을 작성한다. 실제 글자 수를 보고하며 분량 목표 미달을 통과로 바꾸지 않는다.
- 공개 stdio MCP로 가지 계획·장면 초안·사건/등장 인용·추적·검토·모의 채택을 실행한다. 원고/영수증/추적 근거의 판본 일치를 확인한다.
- 중간의 모델 요청과 작가 결정 대기에서 MCP를 종료한 뒤 새 클라이언트로 상태부터 읽어 재개한다. 원고 중복·기록 중복·질문 소실을 검사한다.
- 새 추적 기준을 추가한 뒤 미보충과 재검토 필요를 구분한다. 원고를 바꾸지 않는 보충과 후속 재검토를 실행하고 최종 미완료 상태를 확인한다.
- 별도 합성 오류 fixture에서 고정 사실 위반을 제출하고 hard 승인 차단을 확인한다. 정상 중편과 오류 fixture의 결과를 분리한다.
- 실제 읽기 화면·설정 사용처·연결도·검토 기록·웹/EPUB·정적 검토 사본을 확인한다. 큰 관계도의 가독성과 목차·내보낸 책의 장 구성을 평가한다.

## B. 기존 사람용 실습책 모의 실습

원본: `/path/to/folio/.local-output/folio-public-guide-20261004/book.md`. 역할 설명과 첫 부탁, 작은 책상 자료→계획→어려운 초안→수정 요청→현재 본문 승인→저장 재조회→다음 날 재연결→웹/EPUB와 전체 백업의 차이를 실습한다.

- 문서의 각 부탁과 성공 기준을 실제 공개 도구에 대응한다. 문서만으로 부족해 개발 문서나 코드로 보완한 지점은 assistance로 기록한다.
- 자료 지원 여부, 자료 보관과 실제 인용 연결의 차이, 승인 범위, 참고 의견 비자동수정, 자기검토, 저장 후 본문 일치, 동일 작업 재개를 확인한다.
- 연결 해제 후 전체 작품을 새 위치로 복사하고 실제 MCP로 복원 상태를 읽는다. 원본을 덮어쓰지 않는다.
- 예전 설명과 현재 동작의 차이, 중편의 추적 인터뷰·확인 범위·내보내기 안내 부족을 원문 위치와 재현 결과로 보고한다.

## 완료 조건과 산출물

실제 분량과 결과물을 남기고, A/B 수용 항목별 PASS/FAIL/미검증을 구분한다. 발견한 문제에는 심각도·원문/코드 위치·영향·재현법·수정 제안을 붙인다. AI가 따라 한 실습을 독립 초보자 사용성 검증으로 승격하지 않는다. 제품 변경이 필요한 재현 버그는 별도 회귀 테스트와 최소 수정으로 이어가며, 대규모 개편은 시작하지 않는다.

산출물: 신규 두 작품과 오류 fixture, MCP 호출/요청 로그, 판본/분량/성능/재연결/백업 증거, 화면과 웹·EPUB, 한국어 결과 보고서. 웹 책·EPUB에는 원고만, 정적 검토 사본에는 관리 기록이 포함되는지 확인한다.
