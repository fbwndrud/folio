# 예시 배포 분리 계획

## 목적과 경계

MCP 패키지에는 기존의 작은 합성 입력만 유지한다. 생성한 작품·이미지·기록장은 Git과 npm 패키지에 넣지 않는다. 작품별 별도 ZIP과 읽기 전용 예시 모음을 `.local-output/`에 준비한다. 공개 업로드는 이 작업에 포함하지 않는다.

## 작업 순서

1. 현재 작품 파일의 상대 경로·관리 이미지·기록장 의존성을 조사한다.
2. 명시적으로 고른 작품만 받는 재사용 가능한 배포 빌더를 만든다. 작품 원본, 기록장과 입력 파일을 그대로 복사한다. SQLite 캐시·잠금 파일·호스트 통신 로그는 제외한다. 링크·경로 이탈·로컬 경로·토큰 노출은 실패로 처리하며 기록장을 수정하지 않는다.
3. 복사한 작품으로 최신 읽기 전용 Studio, Web, EPUB를 다시 만든다. 모의 승인과 실제 작가 승인 대기를 화면·안내서·manifest에 구분한다. 파일별 hash와 ZIP checksum을 작성한다.
4. 단편·그림책·안내서·중편·AI 조사서 다섯 묶음과 다운로드 모음을 준비한다. 전체 모음은 전용 로컬 정적 서버로 확인하고, README와 Studio의 예시 안내에서 배포 구조·열기 방법을 설명한다. 미게시 다운로드 URL을 만들어 내지 않는다.
5. 합성 fixture로 링크·노출·손상·중복 출력·기록장 보존을 검사한다. 실제 ZIP은 다른 폴더에 해제하여 진단·이미지 hash·Studio/Web/EPUB를 확인한다. npm 설치본에는 생성된 예시가 들어가지 않음을 검사한다.

## 완료 조건

- 다섯 ZIP 모두 원고·이미지·자료·관리용 작품 사본·Studio·Web·EPUB를 함께 제공한다.
- 원본 기록장 파일은 바이트 단위로 보존하고 실제 작가 승인을 추가하지 않는다.
- 다운로드한 사본을 다른 위치에서 열어도 로컬 원래 경로에 의존하지 않는다.
- 영어/한국어 예시 안내, 좁은 화면과 실제 다운로드를 확인한다.
- 테스트·lint·typecheck·설치 패키지 검증을 통과한다.
- 결과와 미게시 상태·라이선스 미결정을 보고한다.

## 이전·복구

기존 데이터 형식 변경과 마이그레이션은 없다. 출력은 새 폴더에만 쓰며 기존 출력은 덮어쓰지 않는다. 실패한 빌드의 자기 소유 출력만 제거한다. 빌더 및 예시 안내를 제거하면 이전 배포 방식으로 복귀한다. ZIP은 변경한 작품을 원본에 덮어쓰기 위한 복원 기능이 아니다.
