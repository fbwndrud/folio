# image pack — 삽화·웹툰 자산 관리 (M7)

## 설계 방향

이미지 생성·편집은 Linivera를 사용하는 호스트가 자신의 도구 또는 외부 API로 수행한다.
Linivera는 제공자별 생성 SDK·모델 선택·API 키·작업 폴링을 구현하지 않는다.
호스트는 생성 결과를 공통 자산 인터페이스로 전달한다. core는 모델·네트워크를 부르지 않는다.

Linivera의 자산 ID는 작품 안에서 유지되는 고유 ID다. 제공자의 이미지 ID는 선택적인
출처 정보이며 이 ID를 대신하지 않는다. 관리 대상은 설명서, 결과의 파일 또는 리소스 참조,
버전과 내용 hash, 엔티티·펼침면 연결, 사용 위치와 승인한 버전의 기록이다.
외부 참조만으로 내용 확인을 못 하면 확인한 이미지처럼 기록하지 않는다.

이미지 내용을 살피는 검토는 호스트가 수행하고, Linivera는 검토 결과와 적용 버전을 기록한다.
같은 호스트가 생성·검토한 결과는 자기검토다. 참고 의견으로 자산을 자동 교체하지 않는다.
원고 저장과 이미지 승인, 전체 책의 제작 완료를 구분한다.

## 현재 상태

공통 관리 기능은 팩 없이 `folio_assets`로 구현되어 있다.
설명서 등록, 파일/URI 인계, 버전 교체, 사용 위치, 고정 검토 목록과 작가 결정,
조회·추가만 되는 이력을 제공한다. 원고 범위·payload·변경 재검사와 연결된다.
기존 YAML과 본문의 `![[asset:<id>]]` 참조도 읽는다.

`folio_assets` 공통 관리에는 image 팩이 필요하지 않다. 아래 `folio_image` 단계 실행에는 image 팩을 추가한다.
이미지 생성·다운로드·디코딩 검사·지면 제작을 엔진이 수행한다고 안내하지 않는다.

## 그림 단계 (M7)

둘째 팩이다. 단계·프리셋은 첫 팩(novel, knowledge)이 준다. `work.yaml` `packs` 에 `image` 를 더하면 쓸 수 있다.

- 그림 실행(`folio_image`, `core/image`): 설명서 → 생성 전 점검(`image-precheck` 검사) → 생성(호스트) → 검토(`image-review` 검사) → 승인 → 커밋.
- 세트: `image.basic`(생성 전 점검 넷 + 그림 검토), `image.placement`(노드 원고의 `![[asset:id]]` 참조). 모두 실험, 참고 의견이다.
- 그림 검토는 같은 호스트의 자기검토다. 영수증은 독립 평가로 적지 않는다(잠금).
